# Ізоляція агентів на Mac mini

Агенти Factory працюють на самому Mac mini (без віртуалки: Xcode і симулятор такі самі швидкі), але від імені окремого користувача macOS `factory` і всередині srt. Мета — агент **не може** прочитати документи, ключі, Keychain чи дані програм власника, змінити сервер Factory (код, базу, токени) чи зайти в чужі проєкти. Покласти сервер (процесор, диск) може — це прийнятно.

```
┌──────────────────────────── Mac mini ─────────────────────────────┐
│  yura (власник)                                                    │
│   ~/Documents, Keychain, Chrome, ~/.ssh          — лише власник    │
│   сервер Factory — лише 127.0.0.1:5874                             │
│     база, server.env, токени                     — лише власник    │
│   /Volumes/dot/Project/* (проєкти, код v4)       — лише власник    │
│        │ 1. свіжий clone репо в теку картки                        │
│        │ 2. запуск агента від імені factory у srt, токени картки   │
│        ▼                                                           │
│  factory (звичайний користувач, без адмін-прав)                    │
│   srt: писати лише в теку картки                                   │
│     /Volumes/dot/factory-sandboxes/<картка>/ — окремий clone       │
│   /Users/factory: свої node/claude/codex, кеш Xcode, симулятори,   │
│     Chrome; мережа — лише дозволені адреси (не :9222, не :5874)    │
│        │ 3. коміти в clone                                         │
│        ▼                                                           │
│  сервер (yura) забирає гілку (git без хуків) і пушить сам          │
└────────────────────────────────────────────────────────────────────┘
```

## Кроки

Кожен скрипт без аргументів лише показує стан і нічого не змінює. `apply` спершу записує старі права в `~/.mastracode/isolation/`, тож відкат повертає саме те, що було.

| Крок | Хто | Команда | Що робить | Відкат |
| --- | --- | --- | --- | --- |
| 1 | власник | `1-server-files.sh apply` | файли сервера (`~/.mastracode/factory-v4`, `~/.docker/config.json`) — лише власнику | `1-server-files.sh rollback` |
| 1 | код | коміт з `MASTRA_HOST=127.0.0.1` + `deploy.sh` | сервер слухає лише цей мак; Tailscale (UI, Funnel) далі працює | `deploy.sh --rollback` |
| 2a | sudo | `sudo 2-system.sh ownership-on` | диск `dot` поважає власників файлів; показує файли, що виявились чужими | `sudo 2-system.sh ownership-off` |
| 2b | власник | `2-system.sh close-dot` | теки верхнього рівня `dot` — 700, сам диск — 711; `factory-sandboxes` лишається відкритою | `2-system.sh open-dot` |
| 2c | sudo | `sudo 2-system.sh add-user` | звичайний користувач `factory` | `sudo 2-system.sh remove-user` (видаляє і `/Users/factory`) |
| 3 | код | — | clone замість worktree, запуск від `factory` у srt, свої CLI для `factory`, git сервера без хуків; потім `chmod 700 ~` | вимикається налаштуванням: без нього все як зараз |
| 4 | разом | — | перевірка: збірка, симулятор, відео, Chrome агента; спроби дістатися файлів власника й сервера мають падати | — |

Що може зламатись:

- **1** — нічого: сервер працює від власника. Перестане відповідати лише прямий `http://<IP-мака>:5874` з локальної мережі.
- **2a** — файли на `dot`, записані з іншого мака чи іншим користувачем, можуть стати чужими (змінити — лише через `sudo chown`). `ownership-on` одразу показує перші такі файли.
- **2b** — програма, що працює від іншого користувача й читає `dot`, втратить доступ.
- **`chmod 700 ~`** — лише після того, як у `factory` є свої node/claude/codex: зараз агент узяв би їх з `~/.nvm` і `~/.local/bin` власника.

Що лишається відкритим навіть після всього: помилка в самому macOS, що дасть права адміністратора (від цього — лише віртуалка); токени, які агент отримує для роботи (GitHub, Firestore) — ними можна нашкодити в тих сервісах; prompt injection у межах прав `factory`; код, який агент пушить, — переглядати.
