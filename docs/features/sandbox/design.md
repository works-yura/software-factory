# Пісочниця, коміти й пуш, очікування рішення людини

Як це працює **зараз** (стан на 2026-11-13). Пропозиції змін — у [backlog](../../changes/backlog.md#пісочниці), розділ «Пісочниці».

## Пісочниця

- **Лише локальна.** Хмарні пісочниці (E2B, платформа Mastra) прибрано в `d5f3548` (2026-11-04); сервер не стартує з іншим `FACTORY_SANDBOX_PROVIDER`, ніж `local`, а поза розробкою вимагає явного `local` (`apps/server/src/mastra/index.ts`). Агент виконує команди прямо на машині від імені користувача сервера, **без ізоляції**.
- **Де.** `$MASTRACODE_LOCAL_SANDBOX_ROOT` (типово `~/.mastracode/web/sandboxes`). Картка: `work-items/<factoryId>/<гілка картки>/<repo>` — одна папка на всі сесії картки (розбір, план, збірка, рев'ю). Ручна сесія: `<sessionId>/<repo>`. Це повний `git clone`, не git worktree (`packages/sandbox/src/work-item-folder.ts`, `local-factory-sandbox.ts`, `github/sandbox.ts`).
- **Гілка.** `factory/item-<id>` (ClickUp і ручні картки), `factory/issue-<n>-…` / `factory/pr-<n>-…` (GitHub), `factory/gitlab-…`, ручна сесія — `user/session-…` (`packages/pipelines/src/shared/work-item-branch.ts`, `packages/session/src/branches.ts`). Перемикання гілки не стирає локальних комітів і незакомічених файлів.
- **Хід розгортання в чаті.** Поки хід чекає на розгортання (клон, гілка, env-файли, команди налаштування), рядок активності замість «Думає» каже, що відбувається: «Розгортаю пісочницю · клоную book_fate (2 з 5) · 12,5 МБ · 40% · 1 хв 15 с». Готове розгортання, що тривало ≥ 5 с, згортається в «Пісочницю розгорнуто за 42 с»; збій лишається до наступного запуску з репозиторієм, кроком і причиною мовою глядача (повідомлення сервера — у підказці). Кроки звітує `SandboxSetupReporter` (`packages/sandbox/src/setup-progress.ts`) з `harness-mastra` `workspace.ts`; байти клону — з `git clone --progress`. Подія `factory_sandbox_setup` іде в потік самої сесії (`packages/server/src/sandbox-setup-progress.ts`): канал Claude Code / Codex або живу сесію Mastra; її не зберігають, тож сторінка, відкрита посеред розгортання, бачить наступний крок.
- **Шаблон середовища (дзеркала)** — [ADR-0039](../../adr/0039-local-environment-template-mirrors-and-session-work.md). Корінь — `$FACTORY_LOCAL_TEMPLATE_ROOT`, типово `<корінь пісочниць>/.factory-template` (вимкнути: `FACTORY_LOCAL_TEMPLATE=off`): `mirrors/<host>/<owner>/<repo>.git` — bare-дзеркало кожного репозиторію, `package-stores/` — спільні сховища pnpm/npm/yarn (лише з `FACTORY_LOCAL_PACKAGE_STORES=on`; імпорт `clone-or-copy`, не жорсткі посилання), `builds/<проєкт>/` — записи збірок, `templates/<проєкт>/` — шаблонна копія для прогріву залежностей. Свіжий чекаут: дешевий `fetch` дзеркала (не частіше ніж раз на 15 с) під локом репозиторію → `git clone --local` (жорсткі посилання, повна історія) → `origin` = GitHub. Немає/зламане дзеркало → мережевий клон, як раніше, а дзеркало відновлюється у фоні; рядок ходу каже «клоную … з дзеркала» чи «з мережі». «Середовище › Шаблон» показує збірки (статус, історія з комітом і тривалістю на репозиторій, тригери: вручну, cron, пуш) — ті самі компоненти, що для віддалених шаблонів.
- **Кеш і сховище роботи — замінні порти** ([ADR-0045](../../adr/0045-repository-cache-and-session-work-are-replaceable-ports.md)). `LocalEnvironmentTemplate` бере `repositoryCache`, `sessionWorkStore`, `sessionWorkSleepStore` і `builds` з опцій; типово — дзеркала й сховища, як вище. Збірки й прибирання збережених/прихованих refs потребують від кешу можливості `LocalRepositories` (локальний bare-репозиторій): без неї — помилка на старті (або явно `builds: false`), мережевого обходу немає.
- **Робота сесії поза папкою.** Після кожного кінця запуску (будь-який харнес) коміти й незакомічене кожного чекауту зберігаються в дзеркалі (`refs/factory/wip/heads/<гілка>`, `refs/factory/wip/tree/<гілка>`), не чіпаючи індекс і робоче дерево. Свіжий чекаут відновлює їх (збережене > гілка GitHub > база; розбіжність — збережені коміти на гілці, GitHub в `origin/<гілка>`, людині — повідомлення). Папку видаляють (закриття картки, видалення, перестворення) лише після перевіреного збереження; закриття картки ще й пушить refs у приховані `refs/factory/wip/*` на GitHub. Пісочниці без роботи засинають за лімітами Factory (типово не більше 5, сон після 2 год; ніколи — де працює агент) — Settings › Середовище › Пісочниці показує їх і має «Зберегти й зупинити»; агент на наступному ході дізнається, що пісочницю відновлено.
- **Між ходами** все лишається на диску; клон і checkout ідемпотентні, команда налаштування пропускається за маркером (`session-sandbox.ts`).
- **Тайм-ауту простою немає.** Пісочниця живе, доки картка не закрита.
- **Картка у фінальній фазі** («Готово», «Скасовано»): `createTerminalStageCleanup` (`packages/runtime/src/terminal-cleanup.ts`) зупиняє живі запуски, відкликає прив'язки, виконує команди прибирання й **видаляє папку картки** (`rm -rf`, `session-retirement.ts`). Видалення сесії видаляє її папку; спільну папку картки — коли нею більше ніхто не користується.
- **Незапушена робота захищена** (ADR-0039): перед видаленням папки робота зберігається в дзеркалі й при закритті картки — на GitHub; збій збереження лишає папку й стає проблемою пісочниці (у «Пісочницях» і `/attention`, вид `sandbox-problem`).

## Коміти, пуш, PR

- **Комітить агент** сам (`git` у терміналі; скіл `factory-build`). Factory комітить лише з кнопки в UI. Автокомітів на зміну фази немає. Без підпису Claude Code ([ADR-0012](../../adr/0012-no-claude-code-attribution.md)).
- **Пушить агент** інструментом `source_control_push_branch` — він уміє пушити лише гілку сесії (`git push -u origin <гілка>`). Автопушу на зміну фази немає.
- **PR** — `source_control_create_change_request`; на дошці з самоперевіркою відмовляє, доки її не пройдено, і закриває PR, якщо голова відрізняється від схваленої.
- **Права.** Клон і пуш — короткоживучий токен GitHub App на кожну операцію, лише в середовищі цього git-процесу (не в URL). У середовищі пісочниці є `GH_TOKEN` для `gh` (PAT організації, якщо задано, інакше токен встановлення).
- **Пуш у main нічим не заблокований у Factory:** для сесій Claude Code без людини `Bash(git:*)` і `Bash(gh:*)` дозволені автоматично, а `GH_TOKEN` є, тож `git push origin main` з терміналу зупинить лише текст скілу або захист гілки на GitHub.

## Коли потрібне рішення людини

- **Як агент питає:** картка питань (`ask_user` у Mastra, `AskUserQuestion` у Claude Code, [ADR-0006](../../adr/0006-questions-through-cards.md)); `submit_plan`; підтвердження інструменту за правилами allow / ask / deny; запропонована автоматизація («Waiting for approval to …»). Маршрут тріажу «Чекає погодження» нічого не паркує: картка йде у «Вхідні», погодження — те, що людина переносить її далі.
- **Стан.** Запуск завершується з причиною `suspended`; у «Потребує вас» — «Агент чекає відповіді» / «План чекає перевірки» (`ParkedRunAttentionProvider`). Список припаркованих тримається в пам'яті: після перезапуску сервера сесія з'являється там, лише коли її знову завантажили.
- **Пісочниця під час очікування** лишається як є; тайм-ауту очікування немає.
- **Claude Code.** Процес CLI завершується (SIGTERM групи, потім SIGKILL); питання записується на диск (`pendingPermission` / `pendingGate`). Відповідь запускає CLI знову з `--resume <claudeSessionId>` у тому ж треді, відповідь — наступним повідомленням.
- **Mastra.** Відповідь продовжує той самий тред (`respondToToolSuspension` / `respondToToolApproval`).

## Як це в оригінальній Mastra

- Factory не знає про хмару: хост передає один `FactorySandbox` (`create`, необов'язкові `template` і `builds`). Повну підтримку мають **E2B** (свій ключ), **платформа Mastra** (лише їхня хмара) і **Docker** (у себе); ~20 інших пакетів (Daytona, Modal, Vercel, Cloudflare…) — через простий колбек без налаштувань і шаблонів. У нас лишився той самий інтерфейс і `CallbackFactorySandbox`.
- **E2B:** одна VM на сесію, старт ліниво; **шаблон середовища** — образ із уже склонованим репозиторієм і виконаним налаштуванням (збирається при першому старті, за розкладом або після пушу; старий працює, поки новий збирається); **пауза** після простою (типово 5 хв) зі збереженням стану; закрита картка — пауза, знищення — лише з видаленням сесії чи репозиторію (призупинені VM в E2B зберігаються й коштують, доки їх не знищать). Git-токен — у кожну команду окремо.
- **Відмінність від нас:** оригінал при закритті картки ставить на паузу, ми присипляємо через git (дзеркало + приховані refs) і видаляємо папку. Збірки середовища (`environment/build*.ts`) працюють і для локального провайдера ([ADR-0039](../../adr/0039-local-environment-template-mirrors-and-session-work.md)).
