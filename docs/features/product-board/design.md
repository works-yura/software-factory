# Дошка «Продукт»

*Що* будуємо: від ідеї до погодженого плану й задач. Код не пише ніколи. Рішення: [ADR-0002](../../adr/0002-boards-in-code.md), [ADR-0003](../../adr/0003-product-phases-and-gates.md), [ADR-0004](../../adr/0004-brief-rules.md), [ADR-0006](../../adr/0006-questions-through-cards.md).

## Фази

```
Вхідні → Дослідження → Бриф → Погодження → Специфікація → Рев'ю специфікації
       → Фази → Рев'ю фаз → Готово / Скасовано
```

| Фаза | Id | Хто | За що відповідає | Документ |
| --- | --- | --- | --- | --- |
| Вхідні | `intake` | — | ідея чи запит | — |
| Дослідження | `enrich` | агент + людина, `product-enrich` | агент питає раундами по дереву рішень (рекомендована відповідь першою), факти шукає сам; звіряє з кодом, документами й іншими картками «Продукту»; проганяє чек-лист прогалин; веде глосарій | `research.md` |
| Бриф | `brief` | агент + людина, `product-brief` | **для клієнта, нетехнічно**: мета, користувачі, сценарії, межі оцінки, особливі випадки, витрати, залежності, фази й оцінка в годинах; дві мовні версії | `requirements.md`, `requirements.<lang>.md` |
| Погодження | `client-review` | людина / клієнт | правки → назад у «Бриф»; кожне зауваження — `FB-<n>-NNN` з рішенням і перевіркою | `feedback/` |
| Специфікація | `spec` | агент + людина, `product-spec` | **технічна, для команди**: дельта до правди області, діаграми (Mermaid), API, дані, безпека, план тестування, критерії GIVEN/WHEN/THEN; контракт з п'яти боків; pre-mortem | `design.md` (дельта) |
| Рев'ю специфікації | `spec-review` | інженери | правки → назад у «Специфікацію» | — |
| Фази | `phases` | агент, `product-phases` | INVEST-задачі із залежностями, фундамент першим; картка «Розробки» на задачу; остання — задача злиття документації | `tasks.md` |
| Рев'ю фаз | `phases-review` | людина | перевірити задачі | — |
| Готово / Скасовано | `done` / `canceled` | — | — | — |

- Бриф уже є або не потрібен: «Вхідні» / «Дослідження» → одразу «Специфікація».
- Робочі фази не стартують самі: людина запускає й веде діалог у чаті сесії.
- Одна сесія агента на картку на всі фази (контекст `product`); у бічній панелі вона — один рядок «Продукт».
- Кожне питання до людини — карткою питань; бухгалтерію агент робить мовчки.
- Сесії Claude Code читають файли скілів через `skill_read` і сторінки в інтернеті (`WebFetch`, `WebSearch`) без підтвердження — для тарифів провайдерів.

## Ворота

Агент викликає `factory_check_product_document`: обов'язкові розділи (основні + типові, які людина не зняла — `waived` з причиною), заборонені заголовки брифу, таблиця особливих випадків, для специфікації — розділи дельти й діаграми, для `tasks.md` — поля задач і залежності. Результат пишеться на картку.

- Бриф → Погодження: перевірка брифу пройшла.
- Рев'ю специфікації → Фази: перевірка специфікації пройшла.
- Фази → Рев'ю фаз: перевірка `tasks.md` пройшла.
- Рев'ю фаз → Готово: створено хоча б одну дочірню задачу.

Один чернетковий MR документів на зміну; людина зливає його наприкінці Фаз. Задачі «Розробки» мають `parentWorkItemId` = картка «Продукту» і текст «Start only after the documentation change request … is merged»; кожна пам'ятає папку зміни (`productChange`). Якщо план змінився після створення задач, «Продукт» коментує їх (`factory_comment_product_task`, лише свої).

## Інструменти сесії

`factory_check_product_document`, `factory_create_work_item` (`parentWorkItemId`, `docsSync`), `factory_comment_product_task`, `factory_list_product_changes`, `factory_read_product_change`, `factory_read_session` (посилання з чату), `factory_list_attachments`.
