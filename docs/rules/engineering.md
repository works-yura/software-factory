# Правила роботи з кодом фабрики

Обов'язкові для людей і агентів, що змінюють v4.

## Репозиторій і коміти

- **Комітити лише свої шляхи:** `git commit -- <paths>`. Спільний індекс може містити чужі підготовлені зміни; чуже не комітиться, не скидається і не ховається в `git stash`.
- **Паралельна робота — у git worktree** (`.claude/worktrees/<agent>`); у `main` — лише fast-forward після ребейзу.
- Пакети — тільки `corepack pnpm`.
- Не запускати форматер, що переписує стиль файлу (лапки, переноси) поза своїми рядками.
- `.env` і секрети не комітяться.

## Поведінка

- **Спершу оригінал.** Перед зміною поведінки — подивитись, як зроблено в Mastra upstream; свідоме відхилення — рядок у `MIGRATION.md` ([ADR-0001](../adr/0001-v4-own-copy-of-mastra.md)).
- **Без тихих запасних шляхів.** Замінюючи чи ізолюючи щось, старий шлях прибирається, а збій видно (помилка, а не мовчазна підміна). Залишити старий шлях можна лише за рішенням людини.
- **Дані не губляться.** Папки БД і файли ключів не перейменовуються без міграції даних.
- **Нова колонка чи таблиця** додається з типовим значенням, яке читає наявні дані.
- **Функція, доступна лише з API, — не готова:** перевіряється шлях у UI від початку до кінця.

## Безпека

- Claude Code — ніколи `bypassPermissions` / `--dangerously-skip-permissions` ([ADR-0013](../adr/0013-claude-never-bypass-permissions.md)).
- Сесії фабрики не пишуть у `~/.claude` людини.
- Деструктивні команди з шляхами-змінними — лише з перевіркою непорожності (`"${dir:?}"`); процеси зупиняються за PID, не `pkill -f` за назвою.
- Дев-БД не читається без дозволу людини.

## Тести

- Кожна зміна поведінки — з тестом поруч; UI — `*.msw.test.tsx`.
- Під час e2e не редагувати файли: дев-сервер стежить за ними й перезапускається, і всі тести падають.
