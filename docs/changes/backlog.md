# Відкрите й відкладене

Те, що ще не стало зміною. Беремо в роботу — переносимо в зміну або задачу й викреслюємо тут.

## Дошки

- Скіл `qa-round` (QA-раунди в `bugs/`).
- Звіт аудиту: зараз гілка картки пушиться без PR — вирішити, чи відкривати чернетковий PR у docs, чи зливати інакше.

## Маршрути надходження

- Події ClickUp у порт подій (`work_item.state_changed` зараз бачить лише опитувач ClickUp, не подійні тригери).
- Підказка статусів у редакторі маршруту: для умови «ClickUp List» пропонувати статуси цього списку (`/web/clickup/lists/:id/statuses`) замість вільного тексту.
- Прибрати прив'язки списків ClickUp (`intake_source_bindings`) і вибір `sourceIds` зовсім, коли старих правил статусів не лишиться (зараз їх читає лише міграція `ClickUpIntegration.migrate`). Умова `source.list` поки не каже, чий це список: коли з'явиться другий трекер зі списками, маршрут має називати й інтеграцію.
- Розмови в коментарях ClickUp зараз працюють лише для Lists, названих маршрутами (раніше — за самою прив'язкою List).

- Тригери-події: порт `IntakeEventSource` і `eventTriggerKind` готові (ADR-0016); бракує адаптера, що публікує події провайдерів (PR відкрито/змерджено/закрито, картка перейшла у фазу, нова таска чи коментар у ClickUp) з їхніми id, і самих видів тригерів із формами.
- Дії після аудиту: `notify` (лист / Slack для термінових знахідок безпеки), `create-follow-up-cards` (картки на «Розробці» зі знахідок) — коли буде безпечно.
- Шаблони маршрутів за розкладом і аудитів (готові «Щотижневий аудит безпеки», «Залежності щопонеділка»).
- Кнопка «Запустити зараз» для маршруту за розкладом (core `Schedules.run`).
- Невдале спрацювання маршруту за розкладом показувати в «Потребує вас» (зараз — лише в історії маршруту).
- Ворота «MR документів змерджено» в коді: поки це текст у картках «Розробки» й питання людині наприкінці Фаз; дошка злиття не перевіряє.
- Перевірка документа не помічає змін файлу після перевірки.
- Крок специфікації «збудувати чи взяти бібліотеку».

## Агенти

- Інструменти ClickUp для агента: коментар і статус таски (зараз ClickUp лише створює картки).
- Чи підхоплює нову мову агентів уже запущена сесія Claude Code (CLI при продовженні може повторювати системний промпт першого ходу) — перевірити; якщо ні, виправити підказку в UI.
- Перевірити на живому PR, що CLI дотримується `attribution` (без «Generated with Claude Code»).

## Логи й креші

- Кілька провайдерів в одній Factory (Firebase + Sentry): агрегатор над `ObservabilityProvider`, інакше назви інструментів конфліктують.
- Другий адаптер крешів через BigQuery-експорт Crashlytics, якщо альфа-API зміниться чи забракне полів.
- Перевірити на живому проєкті: Cloud Logging і Crashlytics v1alpha відповідають так, як у тестах (тести — лише на підробленому Google); чи приймає Crashlytics ID проєкту замість номера.
- Профіль аудиту «логи» для щоденного аналізу — частково закрито профілем `stability`; вирішити, чи потрібен окремий щоденний.

## Вкладення

- Фаза 2: файли з ClickUp у вкладення картки (`AttachmentService.ingest`, `source: 'clickup'`, `sourceUrl`).
- Фаза 3: файли з GitHub/GitLab (issue, PR/MR); S3-реалізація `AttachmentBlobStore` для кількох реплік.
- Класти вкладення в пісочницю під час її старту, а не лише за викликом `factory_list_attachments`.
- Запис у віддалену пісочницю повільний для великих файлів (base64 через командний канал); перевірено лише на заміннику.

## Пісочниці

Пропозиція (2026-11-11), ще не рішення. Як зараз — [features/sandbox](../features/sandbox/design.md).

- **Присипляння замість паузи.** Не тримати на диску купу клонів і запущених процесів. Присипити = закомітити все незакомічене (разом із новими файлами) окремим WIP-комітом → запушити в прихований ref `refs/factory/wip/<картка>` (не звичайна гілка: не засмічує список і не будить CI) → зупинити процеси → видалити папку. Працює однаково для локальної пісочниці, Docker і хмари, бо на рівні git.
- **Відновлення** при наступному повідомленні чи старті агента: клон → checkout гілки → WIP-коміт назад як незакомічені зміни (`reset --soft`) → команда налаштування. Агентові сказати, що пісочницю відновлено і що ігнорованих файлів (`node_modules`, збірки, локальні `.env`) і запущених dev-серверів уже немає.
- **Ліміти.** Не більше N активних пісочниць (напр. 5); понад ліміт присипляються ті, що найдовше без роботи; окремо — усі, неактивні довше за T (напр. 2 год). Ніколи не присипляти пісочницю, де агент зараз працює; ту, що чекає відповіді людини, — можна (процесу агента там немає).
- **Закриття картки:** спершу присипляння (WIP-пуш), потім видалення — нічого не губиться; WIP-ref прибирати через певний час.
- **Невдалий WIP-пуш** (мережа, права) — папку не видаляти, показати в «Потребує вас».
- **Конфлікт при відновленні** (у гілку запушили, поки спала) — явна поведінка: rebase або питання людині, без мовчазного перезапису.
- **Швидкість відновлення:** спільне сховище git-об'єктів на репозиторій (клон через `--reference`) і спільний кеш pnpm — щоб відновлення займало секунди, а не хвилини.
- **Ізоляція:** Docker-пісочниця з оригіналу (`workspaces/docker`, реалізує `FactorySandbox`) як основна локальна; E2B — опція для команди чи сервера. Перед поверненням E2B з'ясувати, чому його прибрали (`d5f3548`).
- **Заборона пушу в main / базову гілку** в правилах дозволів Factory (зараз `git`/`gh` у терміналі для сесій Claude Code дозволені автоматично, `GH_TOKEN` у середовищі).
- **Список «Потребує вас» після перезапуску** — відновлювати з диска, а не лише з завантажених сесій.
- **Тайм-аут очікування відповіді** — чи потрібен і що тоді (нагадування, а не скасування).

## Відомі вади

- Закриття чи видалення картки видаляє папку пісочниці без перевірки незапушеної роботи — незапушене зникає (див. «Пісочниці»).

## Надходження: після ADR-0022

- ~~Модуль міграцій старту з позначками «виконано»~~ — зроблено (`server/src/migrations/`, `factory_boot_migrations`).
- ~~GitHub на маршрути (рішення (а))~~ — зроблено: репозиторії, які читає проєкт, — це GitHub-маршрути на `source.repository`; міграція `intake.githubRepositorySelections.v1`.
- GitLab на маршрути: підписка досі — вибір `sourceIds` + прив'язки (`intake_source_bindings`), бо ідентифікатор джерела GitLab — непрозорий `gitlab-project:…` (хост + id проєкту), а умова маршруту — шлях проєкту; міграція має зіставити їх через прив'язані репозиторії. Потім прибрати прив'язки, `PUT /web/intake/bindings` (UI його вже не викликає) і переїзд карток при зміні дошки прив'язки.
- `GET /web/intake/items` (агрегована стрічка за всю організацію) досі читає `sourceIds`; UI її не викликає — прибрати або перевести на маршрути проєкту.
- Переписати збережені маршрути в канонічну форму (явна умова джерела) й прибрати код сумісності (`candidates`, `leaf`, `named`, виведення джерела, «задана через API»). Рішення для `in ['github','gitlab']`: переписати на провайдерів, з якими в Factory є прив'язані репозиторії (для syncts і post-airborne — лише GitHub); якщо обидва — розділити на маршрут на кожного, зберігши порядок. Вбудовані маршрути upstream отримують канонічні умови, які можна редагувати. ClickUp-маршрути статусів теж отримують явне `source.integration = clickup`.
- Описи джерел (назва, доступність, іконка) замість назв провайдерів у UI; реєстр джерел у точці збирання замість змінного модульного реєстру.
