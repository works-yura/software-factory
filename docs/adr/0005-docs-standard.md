# 0005. Єдиний стандарт документації проєкту

Дата: 2026-11-10 · Статус: прийнято · Коміти: `15f52ab`, `e32e004`, `d55b533`, `486cc8f`, `2519ae0`, `f5aecae`, `c5d0e27`

**Контекст.** У проєктів (Syncta, PostAirborne, book_fate) документація лежала по-різному й ділилась на бек / фронт; агенти не знали, де правда, а де історія.

**Рішення.** Один стандарт для всіх, включно з самою фабрикою: [rules/docs-standard.md](../rules/docs-standard.md). Одна папка на проєкт; `blackbox/` — незмінна історія; `features/<область>/design.md` — правда «як зараз»; `changes/<дата>-<зміна>/` — дельти в моделі OpenSpec; далі `bugs/`, `audits/`, `rules/`, `runbooks/`, `repositories/`, `client/`, `design/`, `tools/`, `adr/`, `GLOSSARY.md`. «Продукт» пише зміни; «Розробка» вливає дельту в правду окремою останньою задачею зміни (`factory-docs-sync`); баги пишуть `bugs/<id>.md`.

**Наслідки.** Скіли тримають робочу копію розкладки (`product-enrich/references/docs-layout.md`). Чужу розкладку скіли читають як відповідні частини й не переносять без запиту.

**Альтернативи.** Документація в кожному репозиторії коду окремо — відкинуто: зв'язки між беком, мобілкою й вебом рвуться.
