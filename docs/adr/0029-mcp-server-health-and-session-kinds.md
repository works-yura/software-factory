# 0029. MCP-сервери: стан, перегляд інструментів, карантин і доступ за видами сесій

Дата: 2026-11-12 · Статус: прийнято

**Контекст.** У списку MCP-серверів не було видно, чи сервер працює (лише «Firestore · 1 Factory»); інструменти показувались лише назвою; новий інструмент, що змінює дані, після оновлення сервера ставав доступним агентам без нагляду. Доступ мав лише «Factory + дошки/фази» з неявним правилом «без дошок — усі сесії, зокрема чат», а приватні сесії учасників не можна було вибрати окремо; назви дошок і фаз ішли англійською, ту саму Factory можна було додати двічі.

**Рішення.**
- **Стан зберігається з сервером** (`health`: стан, інструменти з анотаціями й схемою, коли перевірено, коли використано, замаскована помилка і її вид). Пише перевірка (`status`, `reconnect`) і реальні виклики сесій; запис стану не змінює `updated_at`, тож запущені сесії не перезапускаються. Модель стану — `McpServerStatus` з mastracode SDK upstream.
- **Перегляд інструментів** — за сторінками MCP у Studio upstream (`packages/playground/src/domains/mcps/components`: список інструментів, «playground» інструмента, список подій), зібрано з дизайн-системи: ризик з анотацій MCP, параметри, політика, «Спробувати» лише для `readOnlyHint` і лише адміну (через хаб, з маскуванням і аудитом `tool_tried`), «Останні виклики» з аудиту з тривалістю.
- **Карантин** — за `doc/MCP-ACCESS-GOVERNANCE.md` з paperclip: новий з минулої перевірки інструмент, що змінює чи видаляє, без своєї політики отримує політику `review` — агентам не видається, доки людина не вибере. Перша перевірка нічого не ховає: людина, що додає сервер, бачить усі інструменти. Для інструментів читання й без анотацій діє типова політика сервера.
- **Ліміт часу виклику** на сервер (типово 60 с, з боку клієнта) і **«Перепідключити»** (зупинити запущені екземпляри, перевірити) — за `doc/MCP-RUNTIME-OPERATIONS.md` paperclip.
- **Помилки людською мовою** за видом: не та версія пакета, не заповнено поле, відмовлено в доступі, тайм-аут, не запускається.
- **Доступ за видами сесій:** у рядку Factory явно «Чат Factory» · «Приватні сесії» · «Картки»; дошки й фази стосуються лише карток і показуються перекладеними назвами; один рядок на Factory. Рядки без видів читаються як мали на увазі (без дошок і фаз — усі три, з ними — лише картки) — окрема міграція даних не потрібна, при наступному збереженні рядок пишеться явно.

**Наслідки.** Людина бачить стан без ручної перевірки, розуміє, що робить кожен інструмент, і не отримує неочікуваних інструментів запису. Анотації — це слово сервера, не гарантія: доступ лише на читання все одно дає роль облікового запису (Cloud Datastore Viewer). Для Claude Code список інструментів «з підтвердженням» визначає вид сесії лише за її id (без ресурсу) — чат, що впізнається лише за ресурсом, рахується як приватна сесія (див. беклог).

**Альтернативи.** Карантинувати всі нові інструменти — відкинуто: зайве тертя для читання. Окрема міграція рядків доступу на старті — відкинуто: читання за старим змістом дає той самий результат без переписування даних.
