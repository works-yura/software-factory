# 0036. Агенти — теж підключення; UI показує лише доступні харнеси

Дата: 2026-11-12 · Статус: прийнято, зроблено: Claude Code, Codex. Продовжує [ADR-0035](0035-connections-server-describes-ui-renders.md).

**Контекст.** Акаунти, на яких працюють сесії Claude Code і Codex (входи Claude і ChatGPT учасників, пул з ротацією й `limited_until`), жили окремо: розділ «Акаунти» в Settings › Моделі, свої маршрути `/web/config/providers/:provider/accounts*`, у UI — таблиця `harnessAccounts` з `'claude-code'`/`'codex'`, перемикач харнесу з трьома зашитими варіантами, крок входу в майстрі створення Factory. Харнес без жодного акаунта однаково пропонувався всюди. Людина: «агентів — теж через Підключення; якщо не підключено, у інтерфейсі цього не має бути взагалі; і стандартизувати, щоб UI легко розширювався».

**Рішення.**
- **Один конектор на харнес з акаунтами, одна реалізація.** `createAgentAccountsConnections` (`packages/api/src/agent-connections.ts`) параметризується дескриптором харнесу (`HarnessDescriptor.setup.accounts: { provider, connector }`, нове поле `icon` — ключ логотипа), видом входу, потоком входу CLI і фасетом використання (`HarnessUsage`). `assembleFactoryApiRoutes` реєструє його для кожного харнесу, який сервер запускає. Категорія каталогу — `agents` («Агенти»), `provides: agent`.
- **Підключення — вхід CLI (`claude auth login`, `codex login`) на машині сервера.** `connect` повертає `authorize` без URL: лише `authId` і `waiting` (заголовок, текст, `timeoutMs`); UI показує нотатку й питає `GET /web/connections/authorizations/:authId`, доки потік не скінчиться; `getAuthStatus` віддає й причину невдачі (`message`). Де сервер не може запустити вхід, спосіб недоступний з причиною.
- **Рядок — акаунт.** Стан словами: підключено; ліміт вичерпано до часу; потрібен вхід (`needs_reauth`); вимкнено; старий вставлений токен (нічого не запускає). `accountDetail` — чий (ваш / ім'я учасника) і план. Дії: перейменувати й видалити — власник або адміністратор; перепідключити (новий вхід) — лише власник. Права оголошено (ADR-0037): `connect: 'member'`, перепідключення — політика `owner`, перейменування, ротація й видалення — `ownerOrAdmin`; перевіряє реєстр.
- **Вплив видалення.** Якщо це останній акаунт власника, з яким пул ще може працювати, — перелічено Factory на цьому харнесі (`stops`), підтвердження обов'язкове, попередження «харнес не пропонуватиметься цьому учаснику»; інакше — «ротація продовжиться на інших».
- **Сторінка підключення — загальні секції.** `facts` (власник, вхід як, план, стан, останнє використання, повернення в ротацію, остання помилка), `table` лімітів (вікна 5 год / тиждень / модель з % і скиданням; читання провайдера не частіше раз на хвилину — спільна `readAccountUsage`), `settings` «Ротація» (перемикач «У ротації»), `table` використання за 7 днів (лише власнику й адміну). Жодного UI під конкретний харнес. Сама ротація й ліміти лишились у пулі сервера.
- **Доступність веде UI.** Фасет моделей називає свій конектор (`HarnessModels.connector`, обгортка `withConnectionAvailability`); Claude Code тепер, як Codex, недоступний людині без власного входу, і `/web/config/models` → `instances[]` несе `available`, `reason`, `connector`. UI (`useHarnessChoices`) поєднує `/web/config/features` → `harnesses` з цією доступністю: перемикач харнесу, «Створити Factory» й онбординг пропонують лише доступні (власний харнес Factory лишається видимим, але вимкненим), вибір моделі ховає недоступні інстанси, а загальна підказка веде на крок підключення конектора (`?add=1&step=connector:<id>`). Settings › Моделі показує акаунти харнесу як посилання на його конектор. Ідентифікатор харнесу в UI — рядок від сервера; MSW-тест рендерить вигаданий харнес «Robo Agent».
- **Прибрано.** Маршрути `/web/config/providers/:provider/accounts*` і `…/accounts/usage` (їх кликав лише UI), розділ акаунтів, діалоги входу й перейменування, `useCredentialAccounts`. `/web/usage/limits` лишився (рядок стану, Аналітика).
- **Mastra лишається в Моделі › Провайдери.** Ключі й OAuth провайдерів моделей — спосіб Mastra дістатися моделей, а не акаунти агентів з ротацією; Mastra доступна завжди (налаштування провайдера пропонує сам вибір моделі). Перенести їх у підключення можна згодом тим самим контрактом.

**Що лишилось.** Крок моделі для Claude Code в «Створити Factory»/онбордингу ще бере аліаси `CLAUDE_CODE_MODELS` і тексти за ключем харнесу (`createFactory.claudeCode.*`, схема чернетки з `z.literal('claude-code')`); `FactoryHarnessModelLabel`, `OnboardingReviewStep`, `usage/format.ts`, `ProviderInstanceIcon` мають мапи за id харнесу. Наступний крок — моделі будь-якого харнесу з `instances[].models`, тексти з `{{name}}`.

**Альтернативи.** Лишити розділ акаунтів у Моделях і лише сховати харнес без акаунта — відкинуто: акаунти — та сама сутність, що й інші підключення (стан, дії, вплив), і другий UI для неї — те, що ADR-0035 прибрав. Окремий конектор на кожен харнес у своєму пакеті — відкинуто: відрізняються лише провайдер, вид входу й тексти, тож одна реалізація з дескриптором.

**Доповнення (2026-11-15, [ADR-0046](0046-cli-sign-in-finished-in-the-persons-browser.md)).** Вхід CLI іде на машині сервера, але сторінка відкривається в браузері людини: статус потоку несе `prompt` (URL, код пристрою або очікування вставленого коду), код приймає `POST /web/connections/authorizations/:authId/code`, скасовує — `DELETE /web/connections/authorizations/:authId`. Спосіб більше не вимкнений поза власною машиною.
