# 0037. Контракт підключень: права в реєстрі, версія, набір перевірок, пакети конекторів, «Активність»

Дата: 2026-11-12 · Статус: прийнято, зроблено. Продовжує [ADR-0035](0035-connections-server-describes-ui-renders.md) і [ADR-0036](0036-agents-are-connections-ui-shows-usable-harnesses.md).

**Контекст.** Після ADR-0035/0036 конектори описують себе, але кожен сам перевіряв ролі (`request.admin ? true : blocked` у шести місцях, `memberManaged` для агентів), контракт не мав версії, перевірки повторювались вручну в кожному пакеті, конектор можна було додати лише в код сервера, а «Активність» і редактор MCP-сервера були винятками з «лише дескриптори». Людина: «доробити все й почати писати тести» — стандарт, що тримається сам.

**Рішення.**
- **Права оголошує конектор, перевіряє реєстр.** `IntegrationConnections.permissions` — `connect`, `reconnect`, `rename`, `remove`, `unlink`, `settings` (для `settings` — і мапа за id секції): `'member'`, `'admin'` (типово, `DEFAULT_CONNECTION_PERMISSIONS`) або `{ policy }` з `policies` конектора (`(request, localId) => true | { reason }`). `buildConnectionRoutes` перевіряє їх на кожному маршруті змін, зокрема `PATCH …/settings`, і сам перетворює в тому, що віддає, заборонену дію, спосіб підключення чи поле налаштувань на `{ reason }`. `ConnectorView.permissions` несе оголошене з типовими. Поведінку збережено: ClickUp — `settings: 'member'` (імпорт вмикає будь-хто), Google Cloud, GitHub, GitLab, MCP — типові адмінські; акаунти агентів — `connect: 'member'`, перепідключення — політика `owner`, решта — `ownerOrAdmin`. Жоден конектор більше не дивиться на `request.admin` для дій. `memberManaged` прибрано. Тест доводить: конектор без жодної перевірки однаково захищений.
- **Версія контракту.** `CONNECTIONS_CONTRACT_VERSION` у `@factory/contracts` (зараз `1.3.0`), `contractVersion` у `/web/connections` і `/web/connections/methods`. Правило сумісності: додати необов'язкове поле, тип секції, категорію, маршрут — мінорна; прибрати чи змінити значення — мажорна. Конектор оголошує версію, яку реалізує (перший сорт — типово поточну); реєстр не обслуговує іншу мажорну (називає у `failures`, його маршрути — 404). Конектор, що не може описати себе, так само ізольовано. UI з іншою мажорною показує «Цю сторінку треба оновити».
- **Набір перевірок.** `describeConnectorContract(label, setup)` з `@factory/integrations/testing`: проти справжнього реєстру — версія; опис і методи; список з глобальними id і діями `true | { reason }`; деталі й вплив видалення; оголошені права для учасника (у маршрутах і у відповідях); ізоляція від збою сусіднього конектора; підключення, перейменування, видалення з 409 до підтвердження; потік `authId`; непорожні тексти en/uk; жодного секрету фікстури в будь-якій відповіді. Його проходять вигаданий конектор, GitHub, ClickUp, GitLab (Platform і серверний токен), Google Cloud, MCP, акаунти Claude Code і Codex та приклад пакета; Codex додатково — наскрізно з підробленим `codex login`. UI: `describeConnectorUi` рендерить будь-яку фікстуру конектора крізь список, сторінку, «Додати» й видалення (Acme Cloud, Robo Agent).
- **Пакети конекторів на старті.** `FACTORY_CONNECTOR_PACKAGES` (`MastraFactoryConfig.connectorPackages`) — модулі, що експортують `connector: { id, contractVersion, create(context) }`. `loadConnectorPackages` імпортує кожен на старті, перевіряє експорт, формат і незайнятість id (перший сорт має перевагу), мажорну версію й фасет. Пакет, що не завантажився, реєструється як конектор, що падає, — сервер стартує, «Підключення» називає його у `failures`. Перший сорт лишається статичним. Зразок — `packages/integrations/examples/connector-example` (Notes Cloud). У продакшені шлях має вести до зібраного JS: сервер не транспілює TypeScript.
- **«Активність» — через реєстр** (перший виняток ADR-0035 прибрано). Необов'язковий фасет `activity(request, { since, limit })`; `GET /web/connections/activity?factoryProjectId&hours` зводить конектори: лічильники, 50 найновіших викликів з глобальним id підключення і конектором, збої окремо. MCP реалізує його з журналу аудиту (`readMcpActivity`); `/web/mcp-servers/activity` прибрано, UI читає реєстр.
- **Редактор MCP-сервера лишається винятком** (другий виняток ADR-0035). Що він робить і чого словник дескрипторів не має: (1) транспорт `stdio | http` перемикає, які поля взагалі є (команда, аргументи, змінні середовища — або URL і заголовки), — потрібна умовна видимість полів; (2) заголовки й змінні середовища — списки пар «ключ → значення», де значення може бути секретом, що не повертається, або посиланням на обліковий запис організації з підказками (`/web/mcp-servers/credential-suggestions`) — потрібне поле-список пар зі змішаними типами значень; (3) інструменти відомі лише після живого підключення (`inspect`), і кожен має свою політику `allow | ask | deny` — потрібна редагована таблиця, рядки якої приходять з окремого виклику; (4) «Спробувати» викликає інструмент з довільним JSON-введенням і показує відповідь — потрібна дія з власною формою й результатом; (5) доступ — матриця «Factory × вид сесії (чат, особисті, картки)»; (6) вибір проєкту чи бази залежить від вибраного акаунта (`/discover`) — каскадні `select`. Описати все це дескрипторами означало б винайти другу мову форм (умови, списки пар, динамічні таблиці, дії з результатом) заради одного конектора — більше коду й менша функція, ніж наявний `McpServerEditor`. Тому сервер лише називає сервер (`custom: mcp-server`, `params`), а новий конектор цим винятком не користується. Повернутися до цього варто, коли другий конектор потребуватиме хоча б двох із цих можливостей.

**Альтернативи.** Лишити перевірку ролей конекторам і лише додати тест — відкинуто: кожен новий конектор повторював би ту саму помилкову можливість забути перевірку; реєстр — одне місце. Версія лише в UI-збірці — відкинуто: сторонні пакети й сервер оновлюються окремо, контракт має бути на дроті. Завантажувати пакети ліниво на першому запиті — відкинуто: помилка пакета має бути видна одразу після старту, а не на чиїйсь сторінці.
