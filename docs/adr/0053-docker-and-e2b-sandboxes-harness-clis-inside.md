# 0053. Пісочниці Docker і E2B; CLI харнесів працюють усередині

Дата: 2026-11-16 · Статус: запропоновано (план, не зроблено). Продовжує [ADR-0048](0048-device-hosts-and-sandboxes-by-capability.md) (п. 4) і [ADR-0050](0050-seatbelt-is-a-factory-setting-xcode-inside.md).

**Контекст.** Зараз пісочниця одна — локальна (`FACTORY_SANDBOX_PROVIDER=local`): агенти на Mac mini від імені `factory` під Seatbelt. E2B колись був і його прибрали (`d5f35480`). У `temp/mastra-fork` є готові `DockerSandbox` і `E2BSandbox` з `FactorySandbox` (шаблони, збірки, налаштування CPU/пам'яті зі схеми). Але Mastra виконує в пісочниці лише команди, а її цикл агента — на сервері; Claude Code, Codex і OpenCode — CLI, що самі виконують інструменти там, де запущені. Тож для них «пісочниця» — це місце, де працює сам CLI. Так влаштовано й у Claude Code з Docker: devcontainer Anthropic — CLI всередині контейнера, файрвол зі списком доменів (API, npm, GitHub), і лише тому там безпечно пропускати дозволи.

**Рішення (план).**
- **Провайдер — налаштування середовища Фабрики**, як ізоляція в ADR-0050: `local` (Seatbelt), `docker`, `e2b`. Форма будується зі схеми провайдера (`FactorySandbox.settings`). Список доступних провайдерів — з того, що є: `docker`, коли демон Docker відповідає; `e2b`, коли в організації є підключення E2B.
- **E2B — підключення організації**, а не змінна оточення: конектор (`integration-e2b`, контракт ADR-0037) зберігає ключ API організації (зашифрований, як інші облікові записи), «Перевірити» звіряє його з E2B. Фабрика вибирає провайдер `e2b` і, коли акаунтів кілька, — акаунт. Без підключення провайдера немає у виборі.
- **Харнеси всередині — через наявну підмінну `spawn`.** Усі три CLI вже запускаються через неї (так зараз — від імені `factory`). Docker: `spawn` стає `docker exec -i -w <тека> <контейнер> <cli> …` — звичайний локальний процес зі stdin/stdout, протоколи харнесів не змінюються. E2B: та сама `spawn` поверх команд E2B (потік виводу, `sendStdin`, сигнали). CLI ставляться в образ (шаблон E2B, образ Docker) разом із тулчейнами середовища.
- **Що досяжне ззовні.** MCP Фабрики (`/mcp`): з Docker — `host.docker.internal`, з E2B — публічна адреса Фабрики з токеном сесії (лише шлях `/mcp`). OpenCode слухає порт усередині: Docker — проброс на loopback хоста, E2B — `getHost(port)`.
- **Мережа.** У контейнері — файрвол зі списком доменів (як `init-firewall.sh` devcontainer): API моделей, реєстри пакетів, git-хости Фабрики. Це й закриває відкритий вихід у мережу, який для локальної пісочниці ще в плані (проксі).
- **Облікові дані** CLI (Claude, ChatGPT) ідуть у пісочницю змінними оточення на час ходу, як зараз агенту `factory`. Проксі облікових даних, щоб токен не потрапляв усередину, — пізніше.
- **Чого ці пісочниці не дають:** iOS і Xcode (Linux). Фабрики з iOS лишаються на `local`; Docker і E2B — для вебу, бекенду, Android.

**Порядок.** (1) Docker: перенести `DockerSandbox`/`DockerFactorySandbox`, `spawn` через `docker exec` для трьох CLI, вибір провайдера в UI, файрвол. (2) Конектор E2B і `E2BFactorySandbox`, `spawn` через E2B. (3) Проксі облікових даних.
