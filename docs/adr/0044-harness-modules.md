# 0044. Harness — це модуль: один інтерфейс, один список

Дата: 2026-11-15 · Статус: прийнято, зроблено (Mastra, Claude Code, Codex, OpenCode). Продовжує [ADR-0036](0036-agents-are-connections-ui-shows-usable-harnesses.md), [ADR-0038](0038-harness-executable-resolution-and-binding-session-invariant.md), [ADR-0043](0043-opencode-harness-free-models.md).

**Контекст.** Кожен harness підключався вручну в п'яти-шести місцях: `packages/server/src/factory.ts` (свій блок створення на кожен harness, ланцюжки `claudeCode ?? codex ?? opencode` для сесій, моделей, чекаутів, паркування, видалення файлів сесії, перемикання harness, старту карток, маршрутизації), `packages/api/src/surface.ts` і `config.ts` (`claudeCodeEnabled`/`codexEnabled`/`openCodeEnabled`, `claudeSignIn`/`codexSignIn`, `checkOpenCodeKey`, `opencodeLocalSessions`, фільтр `HARNESSES` за id), `apps/server` (конфіг кожного harness з env). Додати harness означало редагувати всі ці файли й не пропустити жодного ланцюжка; частина ланцюжків уже розійшлася (OpenCode не був у деяких).

**Рішення.**
- **`FactoryHarnessModule`** (`@factory/harness/module`) — загальна форма модуля: `descriptor` (`HarnessDescriptor`, тип переїхав у `@factory/harness/descriptor`, `@factory/contracts` його реекспортує), `configKey` (ключ конфігу хоста; harness працює, лише коли конфіг його має), `prepare(config, boot)` → `{ usage?, create(host) }`. Два етапи: на старті — виконуваний файл і фасет використання (сесії спостерігаються з першого ходу), потім `create` з усім, що хост дає для сесій. `FactoryHarnessRunning` — мінімум запущеного harness: `descriptor`, `route` (для `createRoutingHarness`), `models` (вже з доступністю). Пакет не залежить ні від сервера, ні від API.
- **Сервер** (`packages/server/src/harnesses/`): `TurnHarnessModule` — `FactoryHarnessModule` з конфігом, `HarnessBootDeps` і `TurnHarnessHost` сервера; `featureFlags` (прапорці `/web/config/features`, які він має), `configFromEnv` (як його налаштовує середовище розгортання). Запущений (`RunningTurnHarness`) дає: рушій сесій, паркування на ліміті, видалення файлів сесії, сесію для чату (і чат Factory), модель сесії для чату, чекаут, особисті сесії, старт карток, `available()` для перемикання, перевірку акаунтів запусків Factory, `joinsSessionRouting` / `asksMidCall` / `mcpSessionTools` (див. нижче) і `api` — прапорці, конектори, власні маршрути. Mastra — базовий модуль (`kind: 'base'`): завжди працює, сесії, яких не тримає інший harness, — його.
- **Один список** — `SERVER_HARNESS_MODULES` у `registry.ts`. З нього виводяться тип конфігу (`HarnessModuleConfigs`: `claudeCode`, `codex`, `opencode` у `MastraFactoryConfig`), `harnessConfigsFromEnv` для `apps/server`, порядок у `/web/config/features` → `harnesses`, у підключеннях і в реєстрі використання. `MastraFactory` проходить список (`prepareTurnHarnesses` → `createTurnHarnesses`, `runtime.ts`) і жодного harness не називає. Додатковий модуль можна дати через `MastraFactoryConfig.harnessModules` і `harnessConfigs` (тест з вигаданим harness).
- **API** (`packages/api/src/harness-modules.ts`): `FactoryApiRoutesDeps.harnesses: HarnessApiModule[]` — кожен відомий серверу harness із `running`, якщо він тут працює. `/web/config/features` бере прапорці (`false` для незапущеного) і дескриптори запущених; конектори Settings › Підключення й власні маршрути (OpenCode: `/web/opencode/local-sessions*`) — з модулів. Спільний конектор входу (ADR-0036) — `signInAccountsConnector`, його кличуть модулі Claude Code і Codex.
- **Код harness — у його теці.** `packages/server/src/claude|codex|opencode/module.ts` — уся проводка harness; фасети використання Claude Code і Codex — `claude/usage.ts`, `codex/usage.ts`; конектор OpenCode і маршрути продовження сесій OpenCode переїхали з `packages/api` у `packages/server/src/opencode/`. Шляхи, ключі конфігу, змінні середовища, збережені дані й відповіді API — без змін.
- **Свідомі відмінності — властивості модуля, не гілки.** `joinsSessionRouting` (повідомлення воркеру з чату Factory, сповіщення вебхуків, пробудження, захист власного id Factory від Mastra-чату): Claude Code і Codex — так, OpenCode — ще ні (як було). `asksMidCall` (MCP-інструменти «з підтвердженням»): лише Claude Code. `mcpSessionTools` (інструменти сесії через MCP Factory і їхні теки скілів): дає Claude Code, як і раніше.

**Що лишилось.** Збережений id harness Factory перевіряє `FACTORY_HARNESSES` у `@factory/store` (білий список збережених значень), а браузер знає дескриптори з `HARNESSES` у `@factory/contracts`: новий harness додає свій id і дескриптор туди (тест сервера звіряє реєстр із ними). UI: тексти «Створити Factory»/онбордингу за ключем harness (`createFactory.<key>`), аліаси моделей Claude Code — як у ADR-0036. Підключити OpenCode до маршрутизації сесій (`joinsSessionRouting`) — окремий крок.

**Альтернативи.** Окремий пакет на серверну частину кожного harness — відкинуто зараз: модулям потрібні сервісні типи сервера (сесії, чекаут, старт карток), а тека в `packages/server/src/<harness>/` уже тримає їх разом без циклу залежностей. Дескриптори в пакетах ядер harness і `HARNESSES` з них — можна згодом; сьогодні `contracts` лишається браузерним каталогом.
