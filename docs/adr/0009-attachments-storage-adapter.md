# 0009. Вкладення через адаптер сховища

Дата: 2026-11-10 · Статус: прийнято · Коміти: `6e638f1`, `1a6e6c3`, `ee05969`, `97f1cd1`, `74b4b8a`

**Контекст.** Файли до задачі приходять з ClickUp, чату й коментарів; агент бачив картинки, але не міг покласти файл у застосунок. Потрібне сховище, яке потім можна замінити на S3.

**Рішення.** Власний інтерфейс `AttachmentBlobStore` (`put`/`get`/`head`/`delete`, ключ — sha256) з реалізацією `LocalFileBlobStore`; записи `factory_attachments` належать картці або сесії; усі джерела заходять через `AttachmentService.ingest`. Агент отримує файли інструментом `factory_list_attachments` у `.factory/attachments/` своєї пісочниці. Будь-яка нова реалізація (S3) має пройти контрактні тести `describeAttachmentBlobStoreContract`.

**Наслідки.** Кілька реплік сервера потребують спільного сховища. Синхронізація ClickUp/GitHub і S3 — `changes/backlog.md`.

**Альтернативи.** `BlobStore` з Mastra — відкинуто: зберігає текст у БД і не має потоків.
