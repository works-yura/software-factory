# 0002. Дошки задаються кодом; «Продукт» не пише код; PR рев'юються на «Розробці»

Дата: 2026-11-10 · Статус: прийнято · Коміти: `23f529d`, `e628d0e`, `2fa2fed`

**Контекст.** Процеси «що будуємо», «як будуємо» і перевірки мають різні фази, ворота й інструменти. Окрема дошка «Рев'ю коду» дублювала кроки «Розробки».

**Рішення.** Кожна дошка — код (`defineBoard`, `packages/pipelines/src/<board>/`), не конструктор в UI; на Factory налаштовуються лише колонки, переходи, автостарт і інструкції фаз. «Продукт» (`product`) відповідає за *що* будуємо і код не пише ніколи; «Розробка» (`work`) — *як*: задача → план → код → PR → рев'ю. Дошку `review` прибрано: усі PR рев'юються в «Розробка › Рев'ю PR».

**Наслідки.** Нова дошка — нова папка в `pipelines` з тестами. Задачі «Розробки», створені «Продуктом», мають `parentWorkItemId`.

**Альтернативи.** Універсальний конструктор дошок — відкинуто: ворота й інструменти кожної дошки не виражаються налаштуваннями.
