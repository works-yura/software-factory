# 0020. Надходження: джерела, а куди йде картка — лише маршрути

> Частково замінено [ADR-0021](0021-one-list-of-intake-routes.md): розклад — маршрут, а не джерело з парним маршрутом; списку «Підключені Lists» немає; ClickUp переносить картки через диспетчер; міграція — на старті.

Дата: 2026-11-11 · Статус: прийнято · Коміти: `4eb7d30`, `f54e795`, `c07d1ab` · Замінює: у [ADR-0015](0015-intake-rules-and-audits.md) й [ADR-0016](0016-intake-rules-ports-and-adapters.md) — «картку ставить маршрут, інакше дошка й фаза правила»; правила статусів списків ClickUp.

**Контекст.** На сторінці «Надходження задач» було три механізми, що відповідали на одне питання «куди йде картка»: маршрути надходження, правила надходження з власною дошкою й фазою і правила статусів кожного списку ClickUp (статус → імпортувати / у фазу й стежити / закрити) з дошкою списку. Кожен мав свій порядок і свій вигляд, тож не було видно, куди насправді піде задача.

**Рішення.**

- **Джерела** лише кажуть, звідки береться картка: списки ClickUp (який список і для якої Factory), «За розкладом» (правило надходження: розклад, назва з `{date}`, опис, політика перекриття), репозиторії GitHub/GitLab («Репозиторії»), «Нова картка». Джерело нікуди картку не ставить.
- **Маршрути** — один впорядкований список, «перший збіг перемагає». «Коли» = джерело + умова; нові умови: `source.list` (список ClickUp) і подія `work_item.state_changed` (статус задачі змінився).
- **ClickUp:** нову задачу списку імпортує маршрут, що називає цей список (`source.list`); ставить її перший маршрут з умовою, що підходить (як і раніше, інші маршрути з умовою мають перевагу). Маршрут на `work_item.state_changed` переносить картку при зміні статусу: у робочу фазу — лише поки картка там, куди її поставив попередній статус (людина чи агент, що її перенесли, тепер нею володіють); у кінцеву фазу — завжди. Задача з типом статусу «closed/done» закриває картку, як і раніше.
- **Розклад:** правило, чия дія створює картку, при створенні отримує свій маршрут «Розклад · <назва>» (`intake.rule` = id → дошка › фаза з дії); при видаленні правила маршрут зникає. Порт `IntakeRuleRoutes` у core, адаптер над збереженими маршрутами в server.
- **Перенесення.** Правила статусів кожного списку стають маршрутами його Factory (див. таблицю) перед кожним проходом опитувача, раз на список; потім правила списку очищаються. Список без Factory чи дошки зберігає правила, доки його не прив'яжуть (раніше вони теж не діяли). Правило надходження без маршруту отримує його під час старту.

| Правило статусу | Маршрут |
| --- | --- |
| `import` | `source.list` = список і `item.state` = статус, на «нова картка» → дошка списку, перша фаза |
| `phase` | та сама умова, на «нова картка» і «статус змінився» → дошка списку › фаза |
| `close` | та сама умова, лише на «статус змінився» → кінцева фаза закриття дошки (`sourceClosed.completed`); дошка без неї — маршруту немає, як і дії раніше |
| `ignore` | маршруту немає |

**Наслідки.**

- Куди піде картка, видно в одному списку; «Правила надходження» як окремий розділ і таблиця статусів у картці списку зникли. Картка списку показує Factory і «→ N маршрутів».
- Опитувач ClickUp не працює без збережених маршрутів (кидає помилку при старті, а не імпортує мовчки).
- Тип джерела «картка правила надходження» лишився як «за розкладом»; маршрути з ним не переносилися.
- Дошка в прив'язці списку більше не використовується опитувачем; її читає лише перенесення старих правил.

**Альтернативи.** Залишити правила статусів у картці списку й лише показати їх поруч із маршрутами — відкинуто: два порядки рішень лишилися б. Зробити розклад умовою маршруту, а не джерелом — відкинуто: розклад створює картку, маршрут лише розміщує.

## Як додати

- **Нове джерело-тригер** — як у [ADR-0016](0016-intake-rules-ports-and-adapters.md#як-додати); його картки розміщують маршрути з умовою `intake.rule` / `intake.trigger`.
- **Нову умову маршруту** — поле в `CARD_RULE_FIELDS` і факт у `cardRuleFacts` (`packages/core`), редактор умови в `apps/ui/src/ui/domains/settings/services/intakeRouteConditions.ts`.
- **Нову подію** — у `STATUS_EVENTS` (`packages/core/src/boards/board-events.ts`); інтеграція, що її бачить, викликає `resolveEventRoute`.
