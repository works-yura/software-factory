# 0003. Фази й ворота дошки «Продукт»

Дата: 2026-11-10 · Статус: прийнято · Коміти: `e628d0e`, `bae618a`, `7b300a9`, `96eb313`, `f2eb38a`

**Контекст.** Між ідеєю клієнта і задачами розробки потрібні дослідження, бриф для клієнта, технічна специфікація для команди й розбиття на задачі — з перевіркою якості на кожному кроці.

**Рішення.** Фази: Вхідні → Дослідження (`enrich`) → Бриф (`brief`) → Погодження (`client-review`) → Специфікація (`spec`) → Рев'ю специфікації → Фази (`phases`) → Рев'ю фаз → Готово / Скасовано. Одна сесія агента на картку на всі фази; робочі фази не стартують самі. Переходи закриті воротами: `factory_check_product_document` має пройти для брифу, специфікації й `tasks.md`; «Готово» — лише з хоча б однією дочірньою задачею. Обов'язкові розділи діляться на основні (не знімаються) і типові (людина може зняти з причиною — `waived`). Дослідження бачить інші зміни «Продукту» в роботі (`factory_list_product_changes`, `factory_read_product_change`). Один чернетковий MR документів на зміну; задачі «Розробки» стартують після його злиття.

**Наслідки.** Перевірка — `packages/pipelines/src/product/documents.ts`; правила тексту брифу — [0004](0004-brief-rules.md). Ворота «MR документів змерджено» поки лише текстом — `changes/backlog.md`.

**Альтернативи.** Окрема фаза «Дизайн» — відкинуто: це і є специфікація.
