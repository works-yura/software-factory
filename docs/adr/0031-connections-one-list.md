# 0031. Підключення: один список Factory, MCP — позначка, акаунти організації під'єднуються

Дата: 2026-11-12 · Статус: прийнято, доповнено того ж дня (див. «Доповнення: внутрішні інтеграції не показують транспорт»). Змінює розділ з [ADR-0027](0027-integrations-services-and-mcp.md) (вкладки «Сервіси» / «MCP» прибрано); модель акаунтів і прив'язок — [ADR-0019](0019-observability-accounts-and-bindings.md), MCP-сервери — [ADR-0025](0025-mcp-servers-manager.md), [ADR-0029](0029-mcp-server-health-and-session-kinds.md).

**Контекст.** Вкладки «Сервіси» і «MCP» ділили підключення за тим, як вони працюють під капотом, а не за тим, що вони дають агентам. Людина бачила «Базу» Google Cloud двічі: у прив'язці й окремим рядком MCP. Акаунти Google Cloud і MCP-сервери — два різні механізми з одним змістом: обидва належать організації, а Factory до них прив'язується. Активність агентів показувалась лише всередині кожного сервера. Взірець — сторінка Connect у Mastra Platform: одна таблиця «інтеграція · підключення · акаунт · можливості · дії», підключення організації під'єднуються до проєкту («Unlink» лишає їх для інших проєктів), один діалог «Add connection» з пошуком по інтеграціях і акаунтах та фільтром, MCP — лише позначка біля назви, «Activity» на тій самій сторінці. Людина: «риалізуй, але не забудь про мобільну адаптацію — це крайнє важливо».

**Рішення.**
- **Сторінка «Підключення»** (той самий шлях `/settings/integrations`, група «Factory») — один список того, чим користуються агенти **цієї Factory**: інтеграція (назва, позначка MCP), акаунт, можливості, стан, меню «⋮». Рядок відкриває свою сторінку (`?connection=…` в URL, тож «назад» на телефоні повертає до списку), де лишаються всі наявні налаштування: прив'язка й акаунт Google Cloud, форма MCP-сервера (доступ за видами сесій, політика інструментів, карантин, «Перевірити», «Останні виклики», маскування), ClickUp, GitHub, GitLab.
- **Два рівні — ті, що вже є в сховищах**, без нової моделі й без міграції даних. Організація: акаунти Google Cloud, MCP-сервери, токен ClickUp, GitHub App, підключення GitLab. Factory: прив'язка Google Cloud (Factory → проєкт через акаунт), рядок доступу MCP-сервера для цієї Factory. **«Відв'язати від Factory»** прибирає лише цю ланку: прив'язку або рядок доступу; акаунт чи сервер лишається для інших Factory. ClickUp, GitHub і GitLab підключено для всієї організації, своєї ланки з Factory у них немає (що саме Factory бере, кажуть маршрути надходження й «Репозиторії»), тож «Відв'язати» для них немає, а рядок підписано «Уся організація».
- **Збірка списку — реєстр видів** (`apps/ui/src/ui/domains/settings/connections/connections.ts`): кожна інтеграція — вид (`CONNECTION_KINDS`: категорія, чи MCP, чи на всю організацію); рядки, каталог «Додати підключення» й акаунти, які можна під'єднати, будуються чистими функціями зі стану самих інтеграцій. Нова інтеграція — новий вид і сторінка деталей, без розгалужень по сторінці.
- **«База» Google Cloud — частина рядка прив'язки** (можливість «База», стан — зі стану її сервера); на сторінці прив'язки — її політика інструментів і маскування. Окремим рядком MCP вона не показується.
- **«Додати підключення»** — одне вікно (див. доповнення; спершу це була бічна шухляда): пошук по інтеграціях і акаунтах організації, фільтр «Усі / Інструменти / Джерела». «Уже є в організації»: акаунт Google Cloud відкриває нову прив'язку через нього для цієї Factory, MCP-сервер під'єднується відразу з доступом для чату, приватних сесій і карток. «Інтеграції»: Google Cloud, сервери каталогу MCP (`server.json`), власний сервер, ClickUp, GitHub, GitLab («Підключено» — для вже підключених). Фільтр «Канали» з Mastra не взято: каналів (Slack, Telegram) у Factory немає; «Джерела» — те, що приносить задачі й код.
- **«Активність»** — виклики інструментів агентами цієї Factory за 24 години: кількість, помилки, останні 50 викликів із сервером, інструментом, тривалістю й посиланням на сесію (`GET /web/mcp-servers/activity?factoryProjectId=&hours=`, з аудиту `tool_called`/`tool_tried`, до 1000 записів, далі — «показано не все»). Записуються лише виклики MCP-серверів; читання логів і крешів у журнал не пишеться — сторінка так і каже, порожнього Google Cloud не вигадує.
- **Телефон — обов'язкова вимога.** Нижче `md` рядок складається: назва з меню «⋮» праворуч, під нею акаунт, можливості, стан; горизонтальної прокрутки немає (перевірено на 360 і 390 px). «Додати підключення» — на весь екран (див. доповнення), фільтри прокручуються вбік, кнопки й меню рядка — не менше 44 px.
- Старі посилання (`?tab=services&service=…`, `?tab=mcp`, `/settings/observability`, `/settings/mcp-servers`) ведуть на те саме місце.

**Наслідки.**
- Одне місце й одна модель для всього, що підключено; «Відв'язати» безпечне — нічого з організації не видаляє. Видалення сервера чи акаунта з організації — окремі пункти меню з підтвердженням.
- Сторінка належить Factory: сервери, що не мають доступу цієї Factory, не видно в списку — їх видно в «Додати підключення».
- Форми деталей ті самі, тож уся перевірка й політика з ADR-0029 працюють без змін.

**Доповнення (2026-11-12): внутрішні інтеграції не показують транспорт; «Додати підключення» — вікно за взірцем Mastra.** Людина: «чому він сирий видний, якщо це інтеграція (внутрішня)? … як вони працюють під капотом, чи MCP чи напряму, це наше діло». Взірець — вікна Mastra Platform «Add connection to project» і «Connect …».
- **Транспорт першої сторони — наша справа.** Запис каталогу MCP може назвати інтеграцію, що запускає його під капотом (`integration` в оверлеї, `mcp-toolbox.factory.json` → `google-cloud`). Такого запису немає серед того, що людина вибирає; сервер з нього — рядок цієї інтеграції («Google Cloud · Firestore», можливість «База»), не MCP. Google Cloud — одна інтеграція з можливостями «Логи · Креші · База»; MCP Toolbox названо лише в згорнутій «Діагностиці» на сторінці підключення (пакет, версія, ідентифікатор сервера, останній стан). Позначка MCP — лише для сторонніх і власних серверів, вони в розділі «Інше» («Власний сервер MCP»).
- **Вікно «Додати підключення»:** по центру, 560 px; угорі пошук і перемикач «Усі / Інструменти / Джерела» (`SegmentedControl`); розділи «Акаунти організації», «Інтеграції», «Інше». Рядок — логотип, назва (MCP — лише стороннім), справа круглі значки можливостей з підказками (ключ — інструменти, вхідні — задачі, гілка — репозиторії) і «+» (з мишею — при наведенні чи фокусі, на дотик — завжди); без описів і кнопок; список прокручується всередині з затуханням донизу. Логотипи — simple-icons (CC0, `simple-icons@16.36.0`), у кольорі бренду; GitHub — кольором тексту, щоб його було видно на темному.
- **Крок «Підключити X» у тому самому вікні:** логотип, «Підключити Google Cloud», один рядок під ним; знизу «← Назад» і головна дія. Google Cloud: акаунт організації (нова прив'язка відкривається на сторінці підключення) або новий сервісний ключ — вставити чи вибрати файл; «Підключаю…», помилка — червонувата панель «Не вдалося підключити» з причиною і «Спробувати знову», успіх — «Вибрати проєкт». ClickUp, GitHub, GitLab: стан («Підключено» / «Ще не підключено» / панель помилки з «Спробувати знову») і їхні власні керування; «Відкрити налаштування».
- **Телефон:** вікно на весь екран (діалог дизайн-системи нижче 640 px стає нижньою шторкою — тут на всю висоту, без заокруглень, з відступами безпечної зони), пошук і перемикач угорі, дія кроку — внизу.
- **Наслідок:** PostgreSQL і власний `tools.yaml` через MCP Toolbox більше не пропонуються в каталозі (запис належить Google Cloud) — їх можна додати як «Власний сервер MCP»; окрема інтеграція баз — у беклозі. Уже збережені сервери Toolbox лишаються: вони показуються рядками Google Cloud «База» і редагуються там.

**Доповнення 2 (2026-11-12): вікно зібрано з компонентів кіта, як у Mastra.** Людина після перегляду: «чому виглядить далеко не так як на скріні? … вони адмінку точно будували на тому кіті що і ми». Розмітка вікна Mastra показала: це `Dialog` (`md`) з `Command` (cmdk) кіта всередині. Тепер так само і в нас: `CommandInput` з пошуком без рамки і `SegmentedControl` (`sm`) у `rightSlot` — в одному рядку (на телефоні перемикач переходить під пошук); `CommandList` у `ScrollArea` з затуханням, висота `min(26rem, 100dvh − 16rem)` — вікно облягає список, без порожнього місця; заголовки груп `text-column`; рядок — `CommandItem` (виділений рядок підсвічує кіт, стрілки й Enter працюють); логотип у звичайному слоті 32 px без рамки; назва `text-body-sm`; MCP — `Badge` `sm`; «+» — ghost-кнопка `icon-sm`, видно на виділеному рядку, на дотик (`pointer-coarse`) — завжди; значки можливостей — маленькі тоновані кружечки (`bg-badge-*-subtle`: інструменти — фіолетовий, задачі — зелений, репозиторії — синій). Крок підключення — ті самі токени: логотип 32 px, заголовок `text-heading`, підзаголовок `text-body-sm`. Рядки списку сторінки — той самий логотип без рамки й `text-body-sm`. Нових розмірів і кольорів поза токенами кіта немає; змін у кіті не знадобилось (`rightSlot` у `CommandInput` уже є).

**Доповнення 3 (2026-11-12): список і сторінка підключення — як живі сторінки Mastra, з компонентів кіта.** Людина: «не гірше», ніж у Mastra.
- **Заголовок сторінки** (`ConnectionsPageHeader`, `PageHeader` кіта в розкладці налаштувань): у списку — «Підключення» і «+ Додати підключення» праворуч (на телефоні — лише «+»), вікно відкривається через `?add=1`; на сторінці підключення — «← Підключення» над заголовком, логотип, назва й значок стану («Активне», «Помилка», «Потребує уваги», «Не перевірено»). Довгий опис і значок «Для всієї Factory» прибрано.
- **Список** — `Table variant="inset"`: Інтеграція (логотип і назва інтеграції) · Підключення (посилання на всю рядок, `Table.RowLink`) · Акаунт · Можливості (тоновані круглі значки з підказкою) · Створено · «⋯». Стан — лише коли щось не так (крапка й слово біля назви, пояснення в підказці). Меню: «Перейменувати», «Перепідключити», «Відв'язати від Factory», роздільник, «Видалити підключення» / «Видалити акаунт з організації» (червоним). На телефоні рядки — складені картки (логотип і назва, інтеграція й акаунт, значки, «⋯»).
- **«Активність»**: період («Остання година / Останні 24 години / Останні 7 днів», сервер приймає `hours`), «Фільтр запитів» — `FilterBar` кіта (підключення, інструмент, результат; «є», «не», «містить», «одне з»), таблиця викликів або порожній стан «Запитів ще немає». Пояснення, що пишуться лише виклики MCP, лишилось одним рядком під заголовком.
- **Сторінка підключення** — вкладки кіта: «Огляд» (Назва з «Зберегти», Акаунт, Створено — коли й ким, Перевірено, Стан, ID підключення з копіюванням), «Активність» (лише цього підключення), і наші: «Доступ», «Інструменти», «Налаштування», «Діагностика» — кожна лише там, де вона має сенс; вкладка — в URL (`&view=`). Форма сервера MCP ділиться на частини (`McpServerEditor section`: `config`, `access`, `tools`), кожна зберігає весь сервер зі свого стану.
- **Перейменування справжнє:** прив'язка Google Cloud отримала необов'язкову назву (`name`) і час та автора створення (`createdAt`, `createdBy` — записуються при створенні, зберігаються при зміні; старі прив'язки показують «не записано»); сервер MCP — свою назву (`label`), а його `createdAt`/`createdBy` з наявних колонок тепер віддаються з API. ClickUp, GitHub і GitLab не мають своєї назви — «Перейменувати» для них немає. Міграції даних не треба: нові поля необов'язкові.
- **Час** — «18 хв тому» мовою інтерфейсу (`TimeAgo`), повна дата в підказці: `RelativeTimestamp` кіта говорить лише англійською.

**Доповнення 4 (2026-11-12): підключення — рівень організації; приватні й персональні підключення — пізніше.** Людина: «у нас налаштування завжди для всієї організації! якщо і є приватний коннект — це пізніше». План окремої ланки Factory для ClickUp, GitHub і GitLab (своя назва в кожній Factory, «Відв'язати від Factory», міграція) відкинуто й не реалізовано.
- **ClickUp, GitHub, GitLab — підключення організації**, їх бачать усі її Factory; меню рядка — дії над підключенням організації: «Відкрити», «Перейменувати», «Перепідключити», роздільник, «Видалити підключення». «Відв'язати від Factory» для них немає. Доступ Google Cloud (прив'язки) і серверів MCP (рядки доступу) лишається, як є: це обмеження доступу Factory до ресурсу організації, а не окремі підключення. Список каже це одним рядком під заголовком.
- **Перейменувати** — власна назва підключення там, де вже лежить його обліковий запис: ClickUp — у метаданих рядка `integration_connections` (`name`; заміна токена її зберігає, як і `connectedBy` — хто підключив уперше; `PATCH /web/clickup/connection/name`); GitHub — колонка `display_name` встановлення (`source_control_installations`, переживає перевстановлення App; `PATCH /web/github/installations/:id`), «Створено» — `created_at` і `connected_by_user_id` встановлення. Старі підключення без назви показують назву акаунта, без автора — «—».
- **Перепідключити** — ClickUp і GitLab: крок «Підключити …» у вікні «Додати підключення» (`&step=`), де замінюється токен / підключення Platform; GitHub App — сторінка встановлення на GitHub.
- **Видалити підключення** — ClickUp: токен організації після підтвердження, яке з даних каже, що перестане діяти (`GET /web/clickup/usage`: Factory і скільки списків ClickUp у їхніх маршрутах надходження).
- **Чого зробити тут не можна — видно, але вимкнено, з причиною під пунктом:** токен у середовищі сервера (GitHub у режимі токена, прямий GitLab) — «Задано в середовищі сервера — змініть змінні середовища»; встановлення GitHub App — «Встановлення GitHub App видаляють на GitHub»; підключення GitLab через Mastra Platform — «Керується в Mastra Platform» (назва й видалення); учасник, не адміністратор — «Лише адміністратор організації».
- GitHub — рядок на кожне встановлення (обліковий запис), як у Mastra; GitLab — на кожне підключення Platform, прямий токен — один рядок.

**Альтернативи.** Спільна таблиця «підключень» у сховищі з міграцією акаунтів і серверів — відкинуто: модель «організація + ланка Factory» вже є в обох сховищах, нова таблиця дублювала б її. Окремі сторінки для організації й Factory, як у Mastra (Organization connections) — відкладено, див. беклог.
