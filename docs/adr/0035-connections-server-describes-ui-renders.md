# 0035. Підключення: сервер описує конектори, UI лише показує

Дата: 2026-11-12 · Статус: прийнято, зроблено: GitHub, ClickUp, GitLab, Google Cloud, MCP-сервери; акаунти агентів — [ADR-0036](0036-agents-are-connections-ui-shows-usable-harnesses.md). Змінює реалізацію [ADR-0031](0031-connections-one-list.md) (сама сторінка, телефон і дизайн-кит — ті самі) і поверхню адміністрування [ADR-0034](0034-github-app-or-token-per-connection.md).

**Контекст.** UI сам складав список підключень зі статусів кожного провайдера (`connections.ts`, реєстр `CONNECTION_KINDS`, `row.kind === 'github'` у списку, деталях, діалогах; окремі компоненти видалення й токена GitHub). Кожна нова дія чи конектор вимагали правок UI, а сервер мав окремі адмін-маршрути на кожного провайдера. Людина: «у UI не має бути нічого, що каже "GitHub" — сервер повертає все, включно з поведінкою».

**Рішення.**
- **Модель — platform-connect Mastra Factory, розширена для прямих конекторів.** Як у `PLATFORM_CONNECT_PROVIDERS` (`packages/integrations/src/platform-connect-routes.ts`, UI `PlatformProviderConnections`): реєстр провайдерів на сервері, у кожного способу `authKind: 'oauth' | 'apiKey'`, загальні маршрути connect/reconnect, рядок підключення з `status: 'active' | 'needs_reauth'`, `accountLabel`, `displayName`. Розширення — для конекторів поза Mastra Platform: поля форми, дії з причинами, вплив видалення, деталі, тексти мовою запиту.
- **Форми взяті з tool-provider Mastra, а не вигадані.** Поле способу — `ConnectionField` з `@mastra/core/tool-provider` (`name`, `displayName`, `description`, `required`, `default`), розширене типами `secret`, `textarea`, `file`; `oauth` повертає `{ url, authId }` як `ToolProvider.authorize`, а `GET /web/connections/authorizations/:authId` — `AuthFlowStatus` як `getAuthStatus`; у конектора — `ToolProviderCapabilities` і `ToolProviderHealth`; назва підключення — `label`. Типи імпортуються з `@mastra/core` 1.82.0, який v4 уже має в залежностях, тож нічого не портовано (і нічого не додано до `THIRD_PARTY_NOTICES.md`). Хуки UI названі й розділені як у `@mastra/react` (`useAllConnections`, `useConnectors`, `useAuthorize`, `useUpdateConnection`, `useDisconnectConnection`) плюс свої (`useReconnect`, `useUnlinkConnection`, `useConnectionImpact`, `useConnectionDetail`). Самі хуки `@mastra/react` не підходять: вони звертаються до маршрутів tool-provider сервера Mastra, а не Factory.
- **Фасет `connections` контракту інтеграції** (`FactoryIntegration.connections(ctx)` → `IntegrationConnections`, `packages/integrations/src/connections.ts`): `describe` (назва, ключ логотипа, категорія, що дає агентам — `provides`, можливості, здоров'я, способи), `list`, `connect(methodId, input)`, необов'язкові `getAuthStatus`, `reconnect`, `rename`, `removalImpact`, `remove({ confirm })`, `unlink`, `detail`. Фасет вирішує все: дії підключення (`rename`, `reconnect: { method }`, `remove`, `unlink`, `manageExternally: { url, label }`) — `true` або `{ reason }`, що показується під вимкненим пунктом; вплив видалення — залежні (Factory), елементи з наслідком `moves | unlinks | deleted | stops` і словами, підпис кнопки; секції деталей — `facts`, `table`, `notice`. Видалення без `confirm` при залежностях — 409 з тим самим впливом.
- **Один реєстр і загальні маршрути** (`buildConnectionRoutes`, змонтовано в `assembleFactoryApiRoutes`): `GET /web/connections?factoryProjectId=`, `GET /web/connections/methods`, `POST /web/connections` `{ connector, method, input }`, `GET /web/connections/authorizations/:authId?connector=`, `POST /web/connections/:id/reconnect`, `PATCH /web/connections/:id`, `GET /web/connections/:id/impact`, `DELETE /web/connections/:id?confirm=1`, `POST /web/connections/:id/unlink`, `GET /web/connections/:id/detail`. Id — `<конектор>:<свій id>`. Лише організація; читати може учасник, змінювати — адміністратор організації (реєстр відмовляє 403 сам); аудит — `factory.integration.*` з ціллю-конектором. Конектор, що не прочитався, названо в `failures`, інші показуються. Інтеграція, не готова на старті, відповідає після `ensureReady`, як її маршрути.
- **Тексти — із сервера, мовою запиту.** UI шле `Accept-Language` з мовою, яку людина вибрала в застосунку; сервер (`connectionLanguage`) бере `uk` або `en`, інакше англійську. Кожен конектор тримає малий каталог `ConnectionCopy<T>` (`{ en, uk }`) у своєму пакеті. UI має лише загальні підписи (кнопки, заголовки колонок).
- **UI лише показує.** Рядок `connector` бере назву, логотип (за ключем — бренд-мітки simple-icons, решта — гліф сервера), стан, «можливості» (іконка за ключем, підпис сервера), дії, тексти з `ConnectionView`. «Додати підключення» будує каталог із `/web/connections/methods`: кілька способів — спершу вибір (недоступний — вимкнений з причиною), `oauth` без полів — перехід за URL, поля — рендер форми з помилками на полі. Видалення — `RemoveConnectionDialog` із впливу. MSW-тести рендерять вигаданий конектор «Acme Cloud», щоб довести, що UI про провайдерів не знає.
- **GitHub перенесено першим.** `GithubConnections` (`packages/integration-github/src/connections.ts`): способи «GitHub App» (`oauth`, лише з App на сервері) і «Токен доступу» (`apiKey`); перепідключення App — потік встановлення, токена — форма; перенесення репозиторіїв при видаленні (ADR-0034) — тепер вплив і `remove`. Старі адмін-маршрути `/web/github/connections`, `/token-connections`, `/connections/:id/usage`, `DELETE /connections/:id`, `PATCH /installations/:id` прибрано (їх кликав лише UI); `/web/github/status`, OAuth, webhook-и, репозиторії лишаються. З UI прибрано `GithubConnections.tsx`, `RemoveGithubConnectionDialog.tsx`, `GitHubService`, `GithubTokenConnect`, `useGithubConnections`. Токени `gh` CLI і власний акаунт GitHub людини переїхали в «Репозиторії» (це про роботу в репозиторіях, а не про підключення організації).

- **ClickUp перенесено.** `ClickUpConnections` (`packages/integration-clickup/src/connections.ts`): одне підключення на організацію (`clickup:org`), спосіб «API-токен» (`apiKey`; коли вже підключено — недоступний з причиною «перепідключіть»), живий стан, перейменування, вплив видалення — Factory, чиї маршрути надходження читають списки ClickUp (`stops`). Перемикач «Імпортувати задачі ClickUp» — секція `settings` деталей (`PATCH /web/connections/:id/settings`, фасет `updateSettings`; реєстр її не обмежує адмінами — поле, яке людині не можна змінювати, сервер вимикає з причиною). Прибрано `PUT/DELETE /web/clickup/connection`, `PATCH …/name`, `GET /web/clickup/usage` і з UI — `ClickUpService`. `/web/clickup/status`, списки й статуси лишились для маршрутів надходження. Посилання `?connection=<конектор>` відкриває єдине підключення конектора, інакше список.

- **GitLab перенесено.** `GitLabConnections` (`packages/integration-gitlab/src/connections.ts`). Режим Mastra Platform: кожен акаунт — підключення (`status`, `accountLabel`, `displayName` з Platform); спосіб «Акаунт GitLab» (`oauth`) повертає не URL, а `session: { provider: 'nango', token, integrationId }` і `authId` — UI проходить вхід Nango без переходу зі сторінки й питає `GET /web/connections/authorizations/:authId`, доки акаунт не стане активним (`AuthFlowStatus`); перепідключення — те саме з reconnect-сесією. Назву й видалення змінюють у Mastra Platform — дії з такою причиною, плюс `manageExternally`. Прямий режим (`GITLAB_ACCESS_TOKEN`): одне підключення з живою перевіркою токена, усі дії — «змініть змінні середовища», спосіб недоступний з причиною. Метадані провайдера з UI-шного `PLATFORM_CONNECT_PROVIDERS` (назва, `authKind`) тепер бере з `/web/connections/methods` і `ProviderConnectControl` у кроці створення Factory. Маршрути `/web/integrations/platform/*` лишились для цього кроку. З UI прибрано `GitLabService` і `orgActions`.

- **Google Cloud перенесено.** `GoogleCloudConnections` (`packages/integration-firebase/src/connections.ts`, конектор `firebase`, логотип і старе ім'я посилань — `google-cloud`, поле `aliases`). Кожна прив'язка Factory — підключення `scope: 'factory'`. Способи: «Новий сервісний ключ» (поле `file` з JSON ключа, назва, проєкт) і «Акаунт організації» (поле `select` з акаунтами). На сторінці підключення — живі перевірки доступу (`notice` на кожну невдалу, з роллю), секція `settings` «Що читає» (проєкт і база Firestore — `select` з того, що бачить акаунт; логи, креші, база — перемикачі; застосунки Firebase — `textarea` по рядку на App ID) і «Акаунт» (назва). «Відв'язати» прибирає прив'язку, «Перепідключити» замінює ключ акаунта, «Видалити підключення» — акаунт разом з усіма його прив'язками, перелічивши їх (`deleted`). Прибрано `PUT/DELETE /web/firebase/accounts/:id`, `/web/firebase/bindings*` (з перевіркою) і пошук проєктів/баз; лишились `GET /web/firebase/status` і `POST /web/firebase/accounts` — його кличе форма MCP-сервера («+ Додати акаунт»), а `AccountKeyDialog` переїхав до редактора MCP. З UI прибрано `GoogleCloudService`, крок підключення Google Cloud, рядки прив'язок і посилання на акаунти.
- **Виняток — редактор MCP-сервера.** Секція `{ type: 'custom', component: 'mcp-server', params }` і поле способу `editor` з тим самим компонентом — єдиний не-дескриптор: редактор транспорту, доступу за Factory й видом сесії і політики кожного інструмента надто багатий для полів. Сервер лише називає сервер (`serverId`, або `owner` + `key` для керованого інтеграцією), UI малює наявний `McpServerEditor`; керований («База» Google Cloud) — без доступу й видалення, лише конфігурація (тільки читання) та інструменти. Так «База» лишилась частиною підключення Google Cloud.

- **MCP-сервери перенесено — останні.** `McpConnections` (`packages/server/src/mcp-servers/connections.ts`) — конектор `mcp`, що не є інтеграцією: реєстр бере його з `assembleFactoryApiRoutes({ connectors })` поруч з інтеграціями. Кожен сервер, до якого має доступ Factory, — підключення `scope: 'factory'` з позначкою MCP і станом словами сервера; «Перепідключити» — спосіб без полів (перевірка), «Відв'язати» прибирає доступ цієї Factory, «Видалити» — сервер для всіх, перелічивши Factory. Способи: «Сервер організації» (`select`), а сервери каталогу й власний сервер — способи з `editor: { component: 'mcp-server', params }`: вибір відкриває сторінку редактора `?connection=new:<конектор>:<спосіб>`. На сторінці сервера — факти, редактор (вкладки «Налаштування», «Доступ», «Інструменти» — для керованого інтеграцією без «Доступу») і таблиця останніх викликів. Маршрути `/web/mcp-servers*` лишились — їх кличе редактор (створення, збереження, перевірка, пошук значень, «Спробувати»).
- **Що лишилось у UI.** `CONNECTION_KINDS`, рядки, побудовані в браузері, і кожна гілка за провайдером зникли: `domains/settings/connections` лише фільтрує каталог і активність, `components/connections` малює `ConnectionView`/`ConnectorView` і секції; ідентифікатори провайдерів — лише ключі логотипів у `ConnectionIcon`. «Активність» сторінки (виклики агентів) читає журнал MCP-викликів — це дані про підключення, не гілка провайдера.

**Альтернативи.** Лишити реєстр у UI і додати серверу лише «дії» — відкинуто: UI далі знав би провайдерів і тексти. Портувати tool-provider Mastra цілком (сховище `tool-provider-connections`, клієнт) — відкинуто: він про OAuth-бакети інструментів агента, а не про акаунти організації з репозиторіями й маршрутами надходження; взято його форми там, де вони збігаються.

**Доповнення (ADR-0036).** Категорія каталогу `agents`; конектор може бути `memberManaged` (права перевіряє сам — кожен учасник керує своїми акаунтами); `authorize` може не мати URL, а лише `authId` і `waiting` для потоку поза браузером; `AuthorizationStatusResponse` несе `message` причини невдачі.

**Доповнення (ADR-0037).** Права оголошує конектор (`permissions`, `policies`), перевіряє реєстр — конектори більше не дивляться на роль; контракт має версію (`contractVersion`); «Активність» іде через реєстр (`GET /web/connections/activity`, фасет `activity`), тож виняток лишився один — редактор MCP-сервера, з поясненням у ADR-0037.
