# 0027. Інтеграції: сервіси й MCP в одному розділі; MCP під капотом сервісів

Дата: 2026-11-12 · Статус: прийнято · Коміти: `3332232a` (сервер), `afd19489` (UI), цей (документація). Уточнює [ADR-0019](0019-observability-accounts-and-bindings.md) і [ADR-0025](0025-mcp-servers-manager.md).

**Контекст.** Підключення були розкидані: GitHub і GitLab — у «Репозиторіях», ClickUp — у «Надходженні задач», Google Cloud — у «Логи і креші», MCP-сервери — окремо в групі «Агент». Базу Google Cloud людина мала б налаштовувати двічі: акаунт у «Логи і креші», а сервер Toolbox — у MCP-формі з тим самим проєктом і акаунтом. Людина просила: один розділ, вкладка «наші інтеграції» (навіть якщо під капотом MCP) і окрема вкладка MCP.

**Рішення.**
- **Розділ «Інтеграції»** (група «Factory», `/settings/integrations`) з двома вкладками; вкладка й відкритий сервіс — у URL (`?tab=services&service=google-cloud`, `?tab=mcp`). Старі адреси `/settings/observability` і `/settings/mcp-servers` переводять туди.
- **«Сервіси»** — наші глибокі інтеграції карткою зі станом, що відкриває свої налаштування: **Google Cloud** (акаунти; прив'язки «Factory → проєкт» з «Логи», «Креші», **«База (Firestore)»**), **ClickUp** (підключення й «Імпортувати задачі»), **GitHub**, **GitLab** (App, токени, підключення). Що Factory читає — далі в «Надходженні задач» (маршрути) і «Репозиторіях» (вибір репозиторіїв), з посиланнями сюди.
- **MCP під капотом сервісу.** Інтеграція оголошує, які MCP-сервери їй потрібні (`FactoryIntegration.managedMcpServers(orgId)` → `ManagedMcpServerSpec[]`, бажаний стан). Google Cloud: прив'язка з «Базою» → MCP Toolbox для Firestore її проєкту (акаунт прив'язки за посиланням, доступ — її Factory). Factory синхронізує їх у сховище MCP-серверів з власником `owner {integration, key}` (`McpServersStorage.syncOwned`): створює, оновлює, прибирає; політику інструментів, маскування й вмикання, які задала людина, зберігає. Синк — після кожної зміни прив'язок чи акаунтів (хук `onManagedMcpServersChanged`) і раз на організацію за запуск перед першим читанням (`ManagedMcpServers.ensure`): сховище не вміє перелічити організації, тож окремого кроку на старті немає.
- **Вкладка «MCP»** показує й сервери сервісів — «керує Google Cloud»: конфіг і доступ лише для читання, змінюються лише політика інструментів і маскування, видалити не можна (API: `409 managed_by_integration`), посилання «Відкрити в «Сервісах»». Поле «акаунт Google Cloud» у формі має «+ Додати акаунт» — той самий діалог, що в сервісі.
- **Перевірка доступу «Бази»** — `listCollectionIds` бази Firestore (scope `datastore`); відмова називає `roles/datastore.viewer`.

**Наслідки.**
- Одне місце для всього, що підключається; базу Google Cloud людина вмикає перемикачем у прив'язці, без MCP-форми.
- Нова глибока інтеграція (Supabase, Sentry): сторінка сервісу + за потреби `managedMcpServers`; проста — запис у каталозі MCP.
- Список дозволених колекцій Firestore не робимо: Toolbox `--prebuilt firestore` його не має; обмеження — роль акаунта (Cloud Datastore Viewer) і політика інструментів. Окремі колекції — через власний `tools.yaml` (беклог).
- «MCP-сервери» більше не в групі «Агент».

**Доповнення (2026-11-12): форма сама знаходить, що доступно.** Поля, які залежать від акаунта, — список того, що він бачить, з можливістю вписати своє: проєкти (Cloud Resource Manager `projects:search`) і бази проєкту (Firestore `databases.list`), заповнені очевидним (проєкт прив'язки Factory чи ключа, `(default)`). Пошук — порт `CredentialProvider.discover`, тож форма MCP лишається загальною: вхід оголошує в оверлеї каталогу `suggest { from, dependsOn }`. Відмова Google не ламає форму — лишаються відомі значення й підказка з роллю (`roles/datastore.viewer` дає обидва списки). Новий сервер з налаштувань Factory починає з доступом цієї Factory; «Перевірити» запускає незбережений конфіг (`POST /web/mcp-servers/check`, нічого не зберігає), тож політику інструментів можна задати до збереження. Деталі й джерела — [features/google-cloud](../features/google-cloud/design.md), [features/mcp-servers](../features/mcp-servers/design.md).

**Альтернативи.** Лишити MCP окремо в «Агенті» — ні: людина вирішила, що всі підключення в одному місці. Окремий менеджер-сервіс (MetaMCP) — див. ADR-0025.
