# 0042. Сповіщення Dependabot як джерело надходження

Дата: 2026-11-14 · Статус: прийнято · Доповнює: [ADR-0022](0022-intake-one-subscription-model-cleanup.md)

**Контекст.** Upstream #30254 (`71684b24b9`) заводить сповіщення Dependabot картками: воркер Platform тягне їх через проксі Platform (`/v1/server/github/repos/:owner/:repo/dependabot/alerts`), а картки ставить власний рушій правил (`integrations/dependabot/{rules,default-rules}.ts`) з опт-іном репозиторіїв у `GithubIntakeSection`. У v4 нема ні Platform, ні цього рушія, ні цієї секції: GitHub працює з власним App або токеном (PAT), а куди лягає картка, вирішують маршрути надходження (ADR-0022). Людина: «переносити все». Переносимо поведінку, не код.

**Рішення.**

- **Синхронізація своїм підключенням.** `packages/integration-github/src/dependabot.ts`: `GithubIntegration.listDependabotAlerts` читає `GET /repos/{owner}/{repo}/dependabot/alerts` через клієнт установки (App або токен — той самий `getInstallationOctokit`, що й для issues): відкриті (до 5 сторінок по 100) і 100 нещодавно закритих (`fixed`, `dismissed`, `auto_dismissed`), щоб виправлення чи відхилення дійшло до картки. Без проксі й без запасного шляху.
- **Відмова названа, не проковтнута.** 403 — бракує дозволу «Dependabot alerts: read» (`permission`), 403 з «disabled» — сповіщення вимкнено в репозиторії (`disabled`), 404 — підключення не бачить репозиторій (`not_found`). Опитування пише стан по репозиторію в `DependabotStatusBoard` (у пам'яті: це рядок стану, наступне опитування його відновлює), Налаштування показують його (`GET /web/github/dependabot/status`).
- **Джерело для маршрутів.** Сповіщення — картка GitHub з типом джерела `dependabot-alert` (`WorkItemSource` `github-dependabot-alert`, ключ `<id репозиторію>#<номер>` — переживає перейменування репозиторію; ключ провайдера `acme/app/dependabot#3`, з якого читається `source.repository`). Умова маршруту бачить `source.kind = dependabot_alert` і нові факти `alert.severity`, `alert.ecosystem`, `alert.package` (джерело GitHub у реєстрі джерел, редактор маршрутів, `CARD_RULE_FIELDS`).
- **Підписка — лише маршрут, що називає вид.** Проєкт бере сповіщення, коли (1) організація ввімкнула перемикач Dependabot (ключ `dependabot` конфігурації надходження, вимкнено до ввімкнення, як #30251) і (2) увімкнений маршрут нових карток називає `source.kind` = `dependabot_alert` (`equals`/`in`) і його умова підходить сповіщенню. Маршрут «усе інше» не підписує: інакше кожне сповіщення кожного прив'язаного репозиторію стало б карткою. Без підписки репозиторій не читається зовсім (жодного запиту до GitHub). Ставить картку диспетчер (`placeArrival`, `skipCatchAll`), як для ClickUp.
- **Старі сповіщення не запускають роботу.** Сповіщення, відкрите до старту сервера, лягає на дошку маршруту в першу фазу (`holdAtInitialPhase`); нове — у фазу маршруту.
- **Закриття.** Виправлене сповіщення — `work_item.closed` з причиною `completed`, відхилене — `canceled`; без маршруту на цю подію картка йде в `sourceClosed` дошки (завершена / скасована). Закрите сповіщення без картки нічого не заводить.
- **Каденція.** Опитування йде у воркері `GithubReconcileWorker` після опитування issues, на його ж каденції і під тим самим lease (App — погодинно, токен — що дві хвилини). Вебхук `dependabot_alert` (коли App підписано на подію) опитує один репозиторій одразу; тіло вебхука не довіряється — сповіщення перечитується через підключення.
- **UI.** Налаштування › Надходження задач: блок «Сповіщення Dependabot» (для Factory з репозиторієм GitHub) — перемикач, попередження «жоден маршрут ще не бере сповіщення», рядок стану по репозиторію (кількість відкритих або чого бракує). Маршрут складається в тому самому редакторі: джерело GitHub, «Тип джерела — Сповіщення Dependabot», за потреби «Серйозність — критична або висока».

**Наслідки.** Нічого не змінюється, доки організація не ввімкне перемикач і не додасть маршрут. Токену (fine-grained PAT) чи App потрібен дозвіл «Dependabot alerts: read»; без нього Налаштування кажуть, якого репозиторію це стосується. Upstream-правил за замовчуванням (за серйозністю в різні фази) нема: це робить маршрут. Стан опитування в пам'яті — після перезапуску рядок «ще не прочитано» до першого опитування.
