# 0023. Ретро процесу Factory поки не робимо

Дата: 2026-11-11 · Статус: відкинуто поки

**Контекст.** Пропонувався процес, який регулярно читає переписки (чати без картки й сесії з карткою), знаходить слабкі місця агентів і запитів людини й пропонує покращення: промпти й інструкції фаз, нові фази, нові дошки, автоматизації. Розглядали два рівні:

- **ретро кожної Factory** — профіль аудиту на дошці «Аудити» (ADR-0015); звіт живе у Factory, не в репозиторії проєкту; прийняте для цієї Factory (інструкції фаз, автостарт, маршрути, типові моделі) застосовується без коду, кожна пропозиція — карткою питань «Прийняти / Відхилити»;
- **ретро платформи** — «мета-Factory», підключена до репозиторію самої платформи: пропозиції змінити скіли, фази чи дошки (код у `packages/pipelines`, ADR-0002) стають картками на її «Розробці»; окреме ретро по всіх Factory читає їхні звіти й шукає спільне. Окремий репозиторій для цього не потрібен.

**Рішення.** Не робимо. Окремий процес аналізу переписок зараз не потрібен; покращення пайплайнів робимо вручну. Ідея «правил, які система сама витягує з минулих розмов» (на кшталт context shards) — теж відкинута.

**Повернутися,** коли повторювані помилки агентів почнуть забирати помітний час на ручне правлення скілів та інструкцій фаз. Почати тоді з першого рівня (ретро однієї Factory), мета-Factory — лише якщо пропозиції виявляться корисними.
