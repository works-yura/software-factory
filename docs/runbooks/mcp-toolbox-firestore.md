# Підключити базу через MCP Toolbox (Firestore, лише читання)

Для кого: адмін організації в Factory і хтось із правом керувати IAM у проєкті Google Cloud клієнта. ~10 хвилин.

## 1. Google Cloud: сервісний акаунт лише для читання

1. Google Cloud Console → проєкт бази (для Syncta — `syncta-57c6a`) → **IAM та адміністрування › Сервісні акаунти › Створити**, напр. `factory-db-reader`.
2. Роль акаунта на цьому проєкті — лише **Cloud Datastore Viewer** (`roles/datastore.viewer`): читання документів, колекцій і запитів. Нічого більше — ні Datastore User, ні Editor. Саме роль гарантує, що змінити базу неможливо, навіть якщо інструмент запису дозволено.
   - Якщо агентам потрібні правила безпеки (`get_rules`, `validate_rules`) — додатково **Firebase Rules Viewer** (`roles/firebaserules.viewer`).
3. Сервісний акаунт → **Ключі › Додати ключ › JSON**. Файл завантажиться; не пересилайте його в чати й не комітьте.

Акаунт для логів (Logs Viewer) і акаунт для бази краще мати окремі: кожен бачить лише своє.

## 2. Factory: сервер

Налаштування › **MCP-сервери** → «Додати сервер»:

- **Назва:** `Syncta Firestore`; **ідентифікатор:** `syncta-db`.
- **Сервер:** «MCP Toolbox for Databases · Firestore».
- **FIRESTORE_PROJECT:** `syncta-57c6a`; **FIRESTORE_DATABASE** — лише якщо база не `(default)`.
- **Service account key (JSON):** вставити вміст файлу з кроку 1.3. Після збереження файл на диску можна видалити.
- «Зберегти».

## 3. Доступ і інструменти

- **Доступ:** «Додати Factory» → `syncts`; щоб базу бачили лише аудити — натиснути дошку «Аудити» (і, за бажанням, фазу «Аналіз»). Без обмежень базу отримують усі сесії Factory, зокрема чат.
- **«Перевірити»:** має показати «Працює: інструментів — 8» (`list_collections`, `get_documents`, `query_collection`, `get_rules`, `validate_rules`, `add_documents`, `update_document`, `delete_documents`). Якщо «Не запускається» — у повідомленні причина (бракує змінної, ключ відкликано, роль чи API).
- **Інструменти, що змінюють дані** (`add_documents`, `update_document`, `delete_documents`), позначені «змінює дані». З роллю Viewer вони однаково отримають відмову від Google; щоб агент навіть не пробував — поставити їм «Заборонено».
- **Маскувати персональні дані** — лишити увімкненим, якщо в базі є дані користувачів (email, телефони).
- «Зберегти».

## 4. Що далі

- Сесії карток, яким призначено сервер, отримують інструменти `syncta-db_*` з наступного ходу.
- Аудит бази за розкладом — маршрут надходження «За розкладом» на дошку «Аудити» з інструкцією, що саме дивитись у базі.

## Вимкнути

- Для всіх — перемикач «Увімкнено» або «Видалити» (секрети видаляються разом із сервером).
- Потім видалити ключ у Google Cloud (Сервісний акаунт › Ключі), щоб він більше нічого не відкривав.
