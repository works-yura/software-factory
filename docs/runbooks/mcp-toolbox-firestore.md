# Підключити базу Firestore для агентів (лише читання)

Для кого: адмін організації в Factory і хтось із правом керувати IAM у проєкті Google Cloud клієнта. ~10 хвилин. Під капотом — MCP Toolbox ([ADR-0027](../adr/0027-integrations-services-and-mcp.md)); окремо його налаштовувати не треба.

## 1. Google Cloud: сервісний акаунт лише для читання

1. Google Cloud Console → проєкт бази (для Syncta — `syncta-57c6a`) → **IAM та адміністрування › Сервісні акаунти**: свій акаунт для Factory (напр. `factory@…`, що вже читає логи) або окремий `factory-db-reader`.
2. Роль акаунта на цьому проєкті — **Cloud Datastore Viewer** (`roles/datastore.viewer`): читання документів, колекцій і запитів. Нічого більше — ні Datastore User, ні Editor. Саме роль гарантує, що змінити базу неможливо. Вона ж дає Factory побачити цей проєкт і його бази у формі (`resourcemanager.projects.get`, `datastore.databases.list`): без неї в списках лишаються лише проєкт ключа й `(default)` з підказкою.
   - Якщо агентам потрібні правила безпеки (`get_rules`, `validate_rules`) — додатково **Firebase Rules Viewer** (`roles/firebaserules.viewer`).
3. Якщо акаунт новий — **Ключі › Додати ключ › JSON**. Файл не пересилайте в чати й не комітьте.

## 2. Factory: «База» в прив'язці Google Cloud

1. Налаштування › **Інтеграції › Сервіси › Google Cloud** (`/settings/integrations?tab=services&service=google-cloud`).
2. Акаунт: якщо його ще немає — «Додати акаунт», JSON-ключ з кроку 1.3 (після збереження файл можна видалити).
3. Прив'язка «syncts → syncta-57c6a» (або «Додати прив'язку»: Factory, акаунт — проєкт заповниться сам, у списку інші проєкти, які бачить акаунт) → увімкнути **«База (Firestore)»**; «База Firestore» заповниться `(default)`, інші бази проєкту — у списку. «Зберегти».
4. **«Перевірити доступ»**: рядок «База syncta-57c6a/(default)» має бути «Є доступ». Якщо ні — у повідомленні роль, якої бракує (`roles/datastore.viewer`), або API, яке треба увімкнути (Cloud Firestore API).

Factory сама створює MCP-сервер Toolbox для цієї прив'язки: у вкладці **Інтеграції › MCP** він «керує Google Cloud» (назва `db-syncta-57c6a`), доступ — лише Factory прив'язки (усі її сесії, зокрема чат).

## 3. Інструменти

У вкладці **MCP** відкрити сервер «Firestore syncta-57c6a»:

- **«Перевірити»:** має показати «Працює: інструментів — 8» (`list_collections`, `get_documents`, `query_collection`, `get_rules`, `validate_rules`, `add_documents`, `update_document`, `delete_documents`).
- **Інструменти, що змінюють дані** (`add_documents`, `update_document`, `delete_documents`), позначені «змінює дані». З роллю Viewer вони однаково отримають відмову від Google; щоб агент навіть не пробував — поставити їм «Заборонено».
- **Маскувати персональні дані** — лишити увімкненим, якщо в базі є дані користувачів.
- «Зберегти». Конфіг і доступ тут не змінюються — їх задає прив'язка.

Обмежити окремими колекціями prebuilt-набір Toolbox не дозволяє; для цього — власний сервер «База даних (MCP Toolbox)» › «Власний tools.yaml» у вкладці MCP. У такій формі «Перевірити» працює ще до збереження: можна одразу побачити інструменти й поставити «Заборонено» тим, що змінюють дані.

## 4. Що далі

- Сесії Factory отримують інструменти `db-syncta-57c6a_*` (напр. `db-syncta-57c6a_query_collection`) з наступного ходу.
- Аудит бази за розкладом — маршрут надходження «За розкладом» на дошку «Аудити» з інструкцією, що саме дивитись у базі.

## Вимкнути

- Вимкнути «Базу» в прив'язці (або видалити прив'язку) — сервер зникне з вкладки MCP.
- Потім, якщо ключ більше не потрібен, — видалити його в Google Cloud (Сервісний акаунт › Ключі).
