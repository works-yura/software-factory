# Підключити логи й креші Firebase

Для кого: адмін організації в Factory і хтось із правом керувати IAM у проєкті Google Cloud клієнта. Займає ~10 хвилин на проєкт.

Як це влаштовано: в організації Factory може бути **кілька акаунтів Google Cloud** (кожен — свій сервісний акаунт і ключ) і **прив'язки** Factory → акаунт → проєкт Google Cloud. Типово — **один акаунт на клієнта, створений у його ж проєкті**. Видати одному акаунту ролі в кількох проєктах теж можна, але не обов'язково ([ADR-0019](../adr/0019-observability-accounts-and-bindings.md)).

## 1. Google Cloud: сервісний акаунт лише для читання

Робиться в проєкті клієнта (наприклад `syncta-57c6a`), тим, хто має там право керувати IAM.

1. Google Cloud Console → вибрати проєкт (той самий ID, що в Firebase › Налаштування проєкту).
2. **IAM та адміністрування › Сервісні акаунти › Створити**: назва, напр. `factory`.
3. Ролі акаунта на цьому проєкті:
   - **Logs Viewer** (`roles/logging.viewer`) — логи сервера;
   - **Firebase Crashlytics Viewer** (`roles/firebasecrashlytics.viewer`) — креші, лише якщо в проєкті є Android чи iOS застосунки (у веб-застосунків крешів у Crashlytics немає).
   Більше нічого: ні Editor, ні Owner, ні Firebase Admin.
4. Для крешів — **API та сервіси › Бібліотека**: увімкнути **Firebase Crashlytics API** (`firebasecrashlytics.googleapis.com`). Cloud Logging API зазвичай уже ввімкнений.
5. Сервісний акаунт → **Ключі › Додати ключ › Створити новий ключ › JSON**. Файл завантажиться; він дає доступ на читання логів і крешів — не пересилайте його в чати й не комітьте. Якщо Google пише «Service account key creation is disabled» — ключі в проєкті заборонені політикою організації; це вирішує власник організації Google Cloud.

*Необов'язково — один акаунт на кілька проєктів:* у другому проєкті **IAM › Надати доступ** → «Нові учасники»: точний email акаунта з першого проєкту (`factory@<проєкт>.iam.gserviceaccount.com`, скопіювати зі списку сервісних акаунтів) → ті самі ролі. Помилка «Email addresses and domains must be associated with an active Google Account…» означає, що такого акаунта немає (опечатка) або проєкт пускає лише свій домен — тоді створіть окремий акаунт у цьому проєкті.

## 2. Factory: акаунт і прив'язка

Налаштування › **Логи і креші** (`/factories/<factory>/settings/observability`), блок **Firebase**.

1. **Акаунти Google Cloud › «Додати акаунт»**: назва (напр. «Syncta»; без назви — проєкт із ключа), вставити вміст JSON або «Вибрати файл ключа» → «Зберегти ключ». У списку видно лише назву й email акаунта; файл ключа на диску після цього видаліть.
2. **Прив'язки › «Додати прив'язку»**:
   - **Factory** — чиї агенти читатимуть (напр. `syncts`);
   - **Акаунт Google Cloud** — через який читати; **ID проєкту Google Cloud** підставиться з ключа, змініть, якщо читаєте інший проєкт;
   - **Номер проєкту Google Cloud** — Firebase › Налаштування проєкту › Номер проєкту;
   - **Логи сервера** — увімкнено, якщо бекенд на Cloud Functions / Cloud Run / App Hosting;
   - **Креші застосунків** — для Android/iOS: застосунки з Firebase App ID (Firebase › Налаштування проєкту › Ваші застосунки, вигляд `1:1234567890:android:0a1b…`), платформою й назвою.
3. «Зберегти», потім **«Перевірити доступ»** — результат одразу під кнопками. Кожен рядок має бути «Є доступ». Якщо ні:
   - «Бракує ролі …» — додати цю роль акаунту в цьому проєкті (крок 1.3);
   - «… API is not enabled» — увімкнути API (крок 1.4);
   - «Google refused the service account key» — ключ видалено або акаунт вимкнено: створити новий ключ, «Замінити ключ» у рядку акаунта.

Друга прив'язка тієї ж Factory (staging, інший клієнт) — ще одна «Додати прив'язку». Тоді агент у кожному виклику називає проєкт.

Приклади: Syncta — проєкт `syncta-57c6a` (номер `650392591794`), лише веб-застосунки → тільки логи. BookFate — `bookfate-prod` (`900351719125`), Android `1:900351719125:android:65f109e838d2590e1a545c` та iOS `1:900351719125:ios:d2efb91effb63e411a545c` → логи й креші.

## 3. Що далі

- Сесії прив'язаної Factory отримують інструменти логів і крешів автоматично (з наступного ходу сесії).
- Аудит стабільності за розкладом: Налаштування › Надходження задач › Правила надходження → правило з дією «створити картку» на дошці «Аудити», в описі `Аудит: stability`.

## Вимкнути

- Один проєкт для Factory — «Видалити прив'язку» в її рядку (або вимкнути лише логи чи креші перемикачем).
- Акаунт — «Відключити» в рядку акаунта; якщо через нього читають прив'язки, Factory покаже їх і видалить разом з акаунтом після підтвердження. Потім видаліть ключ у Google Cloud (Сервісний акаунт › Ключі), щоб він більше нічого не відкривав.
