# Підключити логи й креші Firebase

Для кого: адмін організації в Factory і хтось із правом керувати IAM у проєкті Google Cloud клієнта. Займає ~10 хвилин на проєкт.

## 1. Google Cloud: сервісний акаунт лише для читання

1. Google Cloud Console → вибрати проєкт Firebase (той самий ID, що в Firebase › Налаштування проєкту).
2. **IAM та адміністрування › Сервісні акаунти › Створити**: назва, напр. `factory-reader`.
3. Ролі акаунта на цьому проєкті:
   - **Logs Viewer** (`roles/logging.viewer`) — логи сервера;
   - **Firebase Crashlytics Viewer** (`roles/firebasecrashlytics.viewer`) — креші.
   Більше нічого: ні Editor, ні Owner, ні Firebase Admin.
4. **API та сервіси › Бібліотека**: увімкнути **Firebase Crashlytics API** (`firebasecrashlytics.googleapis.com`). Cloud Logging API зазвичай уже ввімкнений.
5. Сервісний акаунт → **Ключі › Додати ключ › JSON**. Файл завантажиться; він дає доступ на читання логів і крешів — не пересилайте його в чати й не комітьте.

Кілька проєктів (Syncta, PostAirborne): ключ поки один на організацію Factory, тож потрібен один сервісний акаунт, якому видано ці ролі в кожному проєкті. Якщо проєкти в різних організаціях Google Cloud і так не вийде — це пункт беклогу «ключ на Factory».

## 2. Factory: ключ і проєкт

1. Налаштування › **Логи і креші** › *Підключення Firebase*: вставити вміст JSON або «Вибрати файл ключа» → «Зберегти ключ». Після збереження видно лише email акаунта. Файл ключа на диску можна видалити.
2. Перемкнутися на потрібну Factory → *Проєкт Firebase цієї Factory*:
   - **ID проєкту** — напр. `syncta-prod`;
   - **Номер проєкту** — Firebase › Налаштування проєкту › Номер проєкту;
   - **Логи сервера** — увімкнено, якщо бекенд на Cloud Functions / Cloud Run / Hosting;
   - **Застосунки** — для кожного: Firebase App ID (Firebase › Налаштування проєкту › Ваші застосунки, вигляд `1:1234567890:android:0a1b…`), платформа, назва.
3. «Зберегти», потім **«Перевірити доступ»**. Кожен рядок має бути «Є доступ». Якщо ні:
   - «Бракує ролі …» — додати цю роль акаунту (крок 1.3);
   - «… API is not enabled» — увімкнути API (крок 1.4);
   - «Google refused the service account key» — ключ видалено або акаунт вимкнено: створити новий ключ, «Замінити ключ».

## 3. Що далі

- Сесії цієї Factory отримують інструменти логів і крешів автоматично (наступний хід сесії).
- Аудит стабільності за розкладом: Налаштування › Надходження задач › Правила надходження → правило з дією «створити картку» на дошці «Аудити», в описі `Аудит: stability`.

## Вимкнути

- Для однієї Factory — «Вимкнути для цієї Factory».
- Для всієї організації — «Відключити» (ключ видаляється з Factory). Потім видалити ключ у Google Cloud (Сервісний акаунт › Ключі), щоб він більше нічого не відкривав.
